# 流水线页面布局

> 从 SKILL.md 提取的页面布局描述，供 AI 操作浏览器时参考。

## 流水线主页

- **顶部右侧**：编辑流水线、启动新构建 两个按钮
- **左侧**：历史执行记录列表
- **中间区域**：
  - **顶部信息栏**：执行状态（成功/失败）、ID、耗时、触发者、git 简要信息、启动变量（鼠标悬浮"查看全部"弹出环境变量浮窗）
  - **页签区域**：执行详情、构建文件、上传文件、产出物报告
    - **执行详情**：按 Job/插件 树状层级显示，点击插件可过滤只显示该插件日志
    - **已知 bug**：运行期间点击历史记录切换时，执行详情可能显示为其他执行日志

## 编辑流水线页面

顶部页签：**流程配置**（默认）、**流水线配置**、**变量设置**、**触发设置**、**代码源**、**流水线版本**、**执行通知**

## 流程配置

### Job 结构

当前流水线有 **1 个 Job**（Linux 机器），包含 **4 个插件**（2026-07-09 实测）：

```
Stage 1（构建触发）
└── 触发器（3 个）：手动触发 / 远程触发 / 定时任务1

Stage 2（使用新版校验工具增量校验全表规则）
└── Job（Linux）
    ├── 插件1: 拉取代码（GIT）— config commit      （xcard-excel-config，commit 触发用）
    ├── 插件2: 拉取代码（GIT）— config schedule    （xcard-excel-config，定时触发用）
    ├── 插件3: 拉取代码（GIT）— （GIT）rain-qa-func
    └── 插件4: Shell 脚本 — claude（曾名 test）
```

> 插件1、2 拉取同一仓库 xcard-excel-config，分别服务于不同触发场景。

Job 卡片垂直排列，每列右侧有**不起眼的蓝色 + 号**按钮，提示"在右侧添加新 Stage"。

### 插件 3：Shell 脚本

| 配置项 | 值 |
|--------|-----|

### 插件通用配置项

每个插件都有的配置：
- **拉取策略**：恢复更新（清除冲突及缓存后拉取）/ 全量更新（删除后重新克隆）/ 增量更新（直接拉取）/ 合并更新
- **启用 Submodule** / **AutoCrlf** / **Git Clean**（可选）
- **执行超时**：900 分钟
- **启用本插件** / **失败时继续** / **失败时重试** / **执行时机**

点击插件 title 可重新选择切换为其他插件类型。

## 触发设置

| 触发方式 | 配置 |
|----------|------|
| **手动触发** | 允许跳过（可跳过部分插件）、使用上次变量 |
| **远程触发** | 通过特定 URL 触发（启动人为最后编辑人） |
| **定时触发** | 定时任务1：周一至周五 10:00（旧版变量格式，需设 `CI_CLAUDE_CHECK_MODE=full` 实现全量检查） |

## 代码源

| 配置项 | 值 |
|--------|-----|
| 类型 | GitLab |
| 代码更新时触发 | 开启 |
| 触发分支规则 | `^.*$`（匹配任意分支） |

## 执行通知

- **失败通知**（开启）：失败时发送，通知内容含流水线名称、执行编号、失败任务
- **成功通知**（开启）：成功时发送

接收人可配置：指定人员、指定角色、指定群聊、项目组所有人。

## 启动构建界面

点击"启动新构建"后弹出 antd Modal 对话框：
- **左侧**：环境变量配置区域
- **右侧**：Stage/Job/插件列表
- **底部**：取消 + 执行按钮

变量是否显示受"变量设置"页签中每个变量的**显示选项**控制：
- 不显示：变量存在但界面上不可见（使用默认值）
- 显示且必填：界面上可见且必须填写
- 满足全部条件时显示：需满足配置的条件才显示
