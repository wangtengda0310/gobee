## 标题规范

**格式**：`【细分】一句话概括问题`

- `【】` 内是模块的**进一步细分**，与 GPM「模块」字段相关但通常更具体。
- 模块 = `武将` → 标题 `【关羽】释放【武圣】后目标未受伤`
- 模块 = `sdk-充值` → 标题 `【pctap】tap 授权登录后无法拉起充值`
- 模块 = `战斗` → 标题 `【回合结束】托管状态下偶发卡死`

**禁止**：把 GPM 模块名原样塞进 `【】` 而不做细分（如模块是「武将」时标题写 `【武将】xxx` 通常不够具体，应写到具体武将或场景）。

## 描述模板（必填）

GPM 描述字段是**富文本编辑器**，纯文本里的 `\n` **不会换行**，会挤成一行（见 #17431 初版）。Agent 必须写入 **HTML 字符串**。

### 结构要求

1. **重现步骤** — 标题 + 有序列表 `<ol><li>…</li></ol>`
2. **实际结果** — 单独段落
3. **期望结果** — 单独段落
4. 三段之间用 `<p>` 分隔，标题用 `<strong>`

### HTML 模板

将占位内容替换为实际文本后，作为 JSON 的 `description` 值：

```html
<p><strong>重现步骤：</strong></p>
<ol>
<li>（步骤 1）</li>
<li>（步骤 2）</li>
<li>（步骤 3）</li>
</ol>
<p><strong>实际结果：</strong></p>
<p>（实际表现）</p>
<p><strong>期望结果：</strong></p>
<p>（预期表现）</p>
```

### 示例（刘彻语音）

```html
<p><strong>重现步骤：</strong></p>
<ol>
<li>进入对局，选用武将刘彻</li>
<li>发动技能「攻守势易」</li>
<li>观察技能语音播放情况</li>
</ol>
<p><strong>实际结果：</strong></p>
<p>技能「攻守势易」语音丢失，无语音播放。玩家反馈该问题尚未修复。</p>
<p><strong>期望结果：</strong></p>
<p>发动「攻守势易」时正常播放对应技能语音。</p>
```

### Agent 构造 helper（Python）

```python
def bug_description(steps: list[str], actual: str, expected: str) -> str:
    items = "".join(f"<li>{s}</li>" for s in steps)
    return (
        f"<p><strong>重现步骤：</strong></p><ol>{items}</ol>"
        f"<p><strong>实际结果：</strong></p><p>{actual}</p>"
        f"<p><strong>期望结果：</strong></p><p>{expected}</p>"
    )
```

### 禁止与注意

- **禁止**仅用 `\n` 拼接纯文本作为 `description`
- 用户提供截图时，`--attach` 上传；图片由 CLI 追加到描述 HTML
- 复现步骤、实际结果、期望结果任一项无法推断时，**先询问用户**，不要留空提交

## 严重程度定级

Agent 根据问题描述对照下表判定 GPM 严重程度选项，**优先匹配最高符合级别**。推断时仍须标注（猜测），与用户描述明显冲突时询问确认。

| GPM 选项 | 级别 | 修复时限 |
|----------|------|----------|
| 致命-S | S · 致命 | 立即解决 |
| 严重-A | A · 严重 | 2 天内 |
| 一般-B | B · 一般 | 1 周内 |
| 建议-C | C · 微小 | 1 个版本 |

### S · 致命（致命-S）

**定义**：阻碍测试、游戏无法继续、数据丢失或严重异常。

| # | 场景 | 示例 |
|---|------|------|
| 1 | 服务器进程 crash | 任一服务端进程挂掉 |
| 2 | 数据回档或丢失 | 用户数据丢失或回退 |
| 3 | 内存泄漏 | 客户端或服务器内存泄漏 |
| 4 | 客户端 crash | 游戏进程异常退出 |
| 5 | 阻断性错误 | 角色放技能时卡住，战斗无法继续 |
| 6 | 无法登录/连接 | 卡在 loading 或登录按钮无响应 |
| 7 | 版本发布错误 | 前后端数据版本不一致；打包后版本号错误 |
| 8 | 功能入口缺失/失效 | 满足条件时按钮不出现或点击无响应（如「军团」入口） |
| 9 | 流程中断 | 主线任务无法完成；无法添加好友等 |
| 10 | 道具复制 | 限购道具可重复购买或重复出售刷货币 |
| 11 | 属性异常 | 升级后属性反而下降 |
| 12 | 高价值掉落/数值异常 | 概率与设计不符（如 1% 掉落实际远高于设计） |
| 13 | 社交关系错误 | 更新后角色配偶等关系数据错乱 |
| 14 | 网络相关丢失 | 弱网卡顿导致道具一次使用产生多次结果或丢失 |
| 15 | 未屏蔽受限内容 | 审核/政策要求隐藏的内容仍可见（如苹果审核时礼包码入口未隐藏） |
| 16 | 设备兼容性 | 常见机型无法安装或无法启动 |
| 17 | 显示失败 | 黑屏、花屏等导致无法继续游戏（如进战斗黑屏） |
| 18 | SDK 错误 | 登录、注册、短信、版号信息错误 |
| 19 | 充值/支付问题 | 充值不到账或到账金额错误 |
| 20 | 性能问题 | 严重卡顿（如 FPS 低于 10 持续 6 秒以上） |

### A · 严重（严重-A）

**定义**：重要功能未实现或严重缺陷，影响正常游戏；逻辑错误；UI、美术资源或数据错误。

| # | 场景 | 示例 |
|---|------|------|
| 1 | 需求不符 | 功能未按设计实现（如无法修改房间名；战斗结束后多出一个返回按钮） |
| 2 | 逻辑错误 | 系统逻辑失效（如已拉黑玩家仍可发消息） |
| 3 | 条件绕过 | 未满足条件即可操作（如 1 级进 5 级副本） |
| 4 | 低价值掉落/数值异常 | 普通道具掉落权重与设计不符 |
| 5 | 配置错误 | 容器内道具类型错误（如 SSR 宝箱开出 SR 卡） |
| 6 | 文本/内容错误 | 提示或剧情文案缺失或错误（如缺铜币却提示金币不足） |
| 7 | 美术资源缺失 | 打包后贴图等资源缺失（如角色贴图缺失） |
| 8 | 碰撞/摆放错误 | 穿墙；NPC 穿树等地图问题 |
| 9 | 资源使用错误 | 道具图标用错（如宝箱用了消耗品图标） |
| 10 | 模型穿模/异常 | 角色穿地；模型接缝可见 |
| 11 | UI 显示错误 | 界面残留异常元素（如宠物表情留在主界面） |
| 12 | 核心音频缺失 | 对局 BGM 缺失 |

### B · 一般（一般-B）

**定义**：显示类问题；错别字或表述不清；不影响游戏进程的小问题。

| # | 场景 | 示例 |
|---|------|------|
| 1 | UI 需调整 | 元素错位或观感差（如道具描述文字溢出框外） |
| 2 | 错别字/歧义 | 提示文案有错别字（如「得到」写错） |
| 3 | 轻微碰撞/摆放 | 边界略偏；角色可轻微穿入物体 |
| 4 | 非核心音频缺失 | 次要按钮音效缺失 |

### C · 微小（建议-C）

**定义**：建议类、易用性/体验类问题。

| # | 场景 | 示例 |
|---|------|------|
| 1 | 界面不友好 | 层级过深（如超过 3 层嵌套菜单） |
| 2 | 设计不友好 | 重复繁琐流程（如每次回选关界面都播展开动画） |
| 3 | 优化建议 | 体验改进（如购买增加二次确认弹窗） |

**Agent 判定要点**：
- 多条规则同时命中时，取**最高**严重级别。
- 充值、crash、数据丢失、无法登录等关键词优先对照 S 级。
- 功能可用但不符合设计、逻辑有误、核心资源缺失 → 倾向 A 级。
- 纯 UI 微调、错别字、非核心音效 → 倾向 B 级。
- 无功能缺陷、仅为体验优化建议 → C 级。

## 版本树选择

执行 `gpm-cli version-tree list`，结合**当前日期**与问题性质推断默认值：

```
公测
 └── 每日更新          ← 周四~周五默认；SDK/热更类问题常用
     ├── 0604
     ├── 0611          ← 周一~周三默认（当周周版本）
     ├── 0618
     └── ...
```

**默认推断规则**（须标注「默认」或「猜测」）：

| 星期 | 默认版本树 |
|------|------------|
| 周一 ~ 周三 | 当周进行中的周版本（如 `0611`） |
| 周四 ~ 周五 | `每日更新` |

- 可根据问题描述灵活调整（如明确属于 SDK 包体问题 → 倾向 `每日更新`）。
- **无论推断结果如何，创建前必须询问用户确认**：「版本树挂 `0611` 还是 `每日更新`？」

**常用 versionTreeId**（2026-06-04，`gpm-cli version-tree list --json`）：

| 展示名 | ID |
|--------|-----|
| 每日更新 | 571 |
| 0611 | 621 |
| 0618 | 622 |

## JSON 构造规范（必读）

GPM v2 创建接口（`gpm-cli issue create`）对名将杀缺陷有特殊要求，**与旧文档/直觉不同**。

### 系统字段 vs 自定义字段

| 类别 | JSON 键 | 值类型 | 示例 |
|------|---------|--------|------|
| 系统字段 | `moduleIds` | 整数数组 | `[81]`（武将） |
| 系统字段 | `versionTreeId` | **整数** | `571`（每日更新）、`621`（0611） |
| 系统字段 | `assigneeId` / `reporterId` | 整数 | `5486` |
| 系统字段 | `issueTypeId` / `priorityId` | 整数 | `1027` / `459` |
| 自定义字段 | `customFields` | **对象数组** | 见下文 |

### 自定义字段：`customFields` 数组

**禁止**在 JSON 顶层写 `custom_142_670` 等键——会报「复现概率不能为空」。

正确写法：每个自定义字段一条，`id` 为字段 ID，`value` **始终是数组**（枚举也要写 `[3621]`）：

```json
"customFields": [
  {"id": 670, "value": [3621]},
  {"id": 671, "value": [3627]},
  {"id": 673, "value": [4136]},
  {"id": 675, "value": [4137]},
  {"id": 702, "value": [3842]},
  {"id": 788, "value": [5486]}
]
```

### 字段 ID 对照（缺陷）

| 字段 ID | code | 含义 | value 示例 |
|---------|------|------|------------|
| 670 | custom_142_670 | 复现概率 | `[3621]` 必现 |
| 671 | custom_142_671 | 严重程度 | `[3627]` 一般-B |
| 673 | custom_142_673 | 发现分支 | `[4136]` 0.0.8-pre-release |
| 675 | custom_142_675 | 修复分支 | `[4137]` 0.0.8-pre-release |
| 702 | custom_142_702 | bug 类型 | `[3842]` 配置 |
| 788 | custom_142_788 | 开发人员 | `[5486]` 用户 ID |

选项 ID 见下文「枚举选项（快照）」；字段 ID 以 `gpm-cli metadata fields 缺陷 --json` 为准。

### 常见错误写法

| 错误 | 后果 |
|------|------|
| 顶层 `custom_142_670: "3621"` | 复现概率不能为空 |
| 用 `modules` 代替 `moduleIds` | 自定义字段可能识别，但版本树无法提交 |
| 同时写 `modules` + `versionTreeId` | 模块不能为空 |
| 用 `versionTree` 代替 `versionTreeId` | 版本树不能为空 |
| `customFields` 里 enum 的 value 写标量 `3621` | 可能失败；统一用数组 `[3621]` |

### 执行方式

Windows PowerShell 传含换行的 JSON 易解析失败。Agent 应优先用 **Python `json.dumps` + subprocess** 调用 `gpm-cli issue create --data`，确保 UTF-8 与转义正确。
