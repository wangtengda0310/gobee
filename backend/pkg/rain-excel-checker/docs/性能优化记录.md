# rain-excel-checker 性能优化记录

## 已完成的优化

### 1. 启用预加载缓存机制 (2025-04-10)

**方案**: `todo-merge跨表规则数据完整性.md` 的 **方案C**

- merge 遍历开始前，从 merge base 预加载一次全量 261 个 sheet
- 所有 commit 共享此缓存，避免重复 git 读取
- 新增 `CheckOption`/`WithFallbackSheetMap` 支持缓存传递

**性能提升**:
- 单个 commit: 22秒 → 3-6秒 (73-86%↑)
- 4个 commit 总计: 88秒 → 57秒 (35%↑)
- sheet 加载次数: 1060次 → 261次 (75%↓)

**相关提交**: `5438425` - perf: 大幅优化 merge 场景性能

### 2. 优化通用规则检查范围 (2025-04-10)

调整执行顺序，将通用规则检查移到 supplement 之前。此时 sheetMap 只包含变更的文件，天然实现"只检查变更"。

- 优化效果: 261 个 sheet → 1-2 个变更 sheet (99%↓)

### 3. 移除欺骗性缓存逻辑 (2025-04-10)

删除错误的缓存读取逻辑，恢复正确的 git show 读取逻辑，确保历史数据对比正确。

### 4. 按需补充关联表 (2025-04-10)

**方案**: 移除全量预加载，改为按需从 git 加载关联表。

- 新增 `collectRequiredSheets` 函数：从规则列表收集所需关联表
- 新增 `isSheetRequired` 和 `mayFileContainRequiredSheet`：灵活的名称匹配
- 移除 `main.go` 中的全量预加载，改为按需从 git 加载

**性能提升**:
- 关联表加载: 全量 239 个 xlsx → 按需 20 个文件中提取 7 个 sheet (97%↓)
- 关联表加载耗时: 41-58秒 → 1.5秒 (97%↑)
- merge 总耗时: 57秒 → 15秒 (74%↑)

### 5. CHAIN_REFERENCE GetCols 缓存 (2026-05-18)

**问题**: CHAIN_REFERENCE 洋葱模型中，每行执行左链/右链时都调用 `targetFile.GetCols()`。Item 表（1329行）的 `GetCols` 调用耗时 ~2.4秒，30行 × 多步骤 = **~200秒**。

**方案**: 在 `ChainContext` 中添加 `ColsCache map[string][][]string`，所有行共用。新增 `GetCachedCols()` 方法替代直接 `GetCols()` 调用。

**性能提升**: ~200秒 → ~4秒（50倍）

**额外修复**:
- 添加引用完整性检查：左链跨表查找无过滤条件时，有输入值但查找结果为空则报错
- 移除4个高频调试日志，减少 Wails Event.Emit 开销

### 6. ArenaSeasonCheckRule 参数解析容错 (2026-04-16)

**问题**: 用户输入错误格式的 `timeRangeBefore` 参数（如 `"7天"`、`"168"`）时，规则直接报错并中断检查。

**修复**: 解析失败时回退到默认值 `168h`（7天），与 `DanQingGeTimeActiveCheckRule` 保持一致的容错策略。
