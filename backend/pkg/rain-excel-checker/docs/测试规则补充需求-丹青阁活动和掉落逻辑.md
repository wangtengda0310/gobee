# 测试规则补充需求 - 丹青阁活动和掉落逻辑

> **需求类型**: 功能增强
> **优先级**: 高
> **创建时间**: 2026-04-10
> **状态**: 待实现

## 需求背景

1. **服务端已实现验证但配表阶段无法发现** — 服务端 `dropConfig.go`、`drawConfig.go` 中的验证只有在服务端加载配置时才会执行，配置错误导致服务启动失败
2. **丹青阁活动和掉落系统缺少验证规则** — 涉及复杂的掉落逻辑，当前缺少针对掉落规则、掉落组、掉落道具的关联验证
3. **跨表关联验证不足** — 掉落系统涉及多表关联(Activity → Draw → DropRule → DropGroup → DropItem → Item)

## 配置关系

```
Activity (丹青阁活动) - ActTypeSkinRaffle (类型=13)
  └─ CustomParma → Draw.Id (抽奖池ID)
       └─ OnceDropRule/TenDropRule → DropRule.Id
            └─ DropRule.DropGroup → DropGroup.Id
                 └─ DropItem.DropGroup → DropGroup.Id
                      └─ DropItem.Item → Item.Id
```

## 需求目标

补充以下验证规则，覆盖丹青阁活动和掉落系统的核心配置验证：

1. **服务端已实现的验证规则**(优先实现)
   - `DROP_RULE_COUNT_POSITIVE_CHECK`
   - `DRAW_DROP_RULE_REFERENCE_CHECK`

2. **掉落系统核心验证规则**
   - `DROP_RULE_GROUP_ID_CHECK`
   - `DROP_ITEM_GROUP_REFERENCE_CHECK`
   - `DROP_GROUP_COMPLETENESS_CHECK`
   - `DROP_ENSURE_CONFIG_CHECK`

3. **丹青阁活动专项验证规则**
   - `DANQINGGE_ACTIVITY_TYPE_CHECK`
   - `DANQINGGE_TIME_CONSISTENCY_CHECK`

## 技术方案

### 实现架构

所有规则均为**跨表验证规则**，实现位置：`rain-excel-checker/xlsx/coded_rules/cross_table/`

### 实现步骤

每个规则的实现必须遵循以下步骤(详见 [跨表规则开发手册](../跨表规则开发手册.md))：

1. **添加规则类型常量**(`json_rule/rule_def.go`)
2. **创建规则实现文件**(`coded_rules/cross_table/`) — 实现 `TableChecker` 接口
3. **注册检查器**(`check_manager/table_check_manager.go`)
4. **配置默认规则**(`json_rule/default_table_rules.go`)
5. **编写单元测试** — 覆盖正常通过、应该失败、依赖不存在等场景

### 关键技术点

- **依赖表加载**：使用 `check_internal.FindSheetBySuffix` 支持中英文表名匹配
- **时间处理**：空时间字符串视为合法(永久有效)，解析失败时记录错误
- **逗号分隔ID解析**：使用 `check_internal.ParseCommaSeparatedIds`
- **错误信息构建**：必须包含表名、ID、具体值等定位信息

> **实现注意事项**：
> - 规则注册位置：`json_rule/rule_def.go`(常量)、`check_manager/table_check_manager.go`(注册)、`json_rule/default_table_rules.go`(默认配置)
> - 时间解析使用 `excel_internal.ParseTime` 或 `excel_internal.ParseDate`，空时间字段视为合法
> - 服务端已实现的验证仍值得在配表检查中复现，以便早期发现问题、提供更友好的错误提示、支持飞书通知

## 验收标准

### 功能验收

- [ ] 所有规则在 `json_rule/rule_def.go` 中定义常量
- [ ] 所有规则在 `check_manager/table_check_manager.go` 中注册
- [ ] 所有规则在 `json_rule/default_table_rules.go` 中配置默认应用
- [ ] 所有规则通过单元测试
- [ ] 错误提示信息包含表名、ID、具体值等定位信息
- [ ] 飞书通知正确显示错误信息
- [ ] MCP 接口正确返回结构化详情

### 测试验收

每个规则必须覆盖：正常通过、依赖数据不存在、引用不存在、空值处理、格式错误。

### 性能验收

- 单个规则检查耗时 < 100ms(1000行数据)
- 所有规则检查累计耗时 < 1s(1000行数据)

## 实现优先级

## 风险与限制

| 风险 | 缓解措施 |
|------|----------|
| 中英文表名匹配失效 | 使用 `FindSheetBySuffix` 支持后缀匹配 |
| 时间格式不一致导致解析失败 | 与服务端保持一致的解析逻辑 |
| 跨表检查耗时较长 | 构建 ID Map 提高查询效率 |
