# 跨表规则开发手册

新增跨表级别校验规则的完整流程。

## 必须完成的步骤清单(缺一不可)

| 步骤 | 文件 | 操作 |
|------|------|------|
| 1 | `json_rule/rule_def.go` | 在 `ETableRule` 枚举中添加常量 |
| 2 | `coded_rules/cross_table/` | 创建规则实现文件和测试文件 |
| 3 | `check_manager/table_check_manager.go` | 在 `init()` 中 `TableManager.Reg(...)` 注册检查器 |
| 4 | `json_rule/default_table_rules.go` | 在 `DefaultTableRules` 中配置默认应用 |

**经验教训**：步骤 4 容易遗漏。如果不配置 `DefaultTableRules`，规则虽然注册了但不会自动执行。

## 步骤 1：添加规则类型常量

在 `json_rule/rule_def.go` 的 `ETableRule` 枚举中添加：

```go
YOUR_RULE_CHECK ETableRule = "YOUR_RULE_CHECK" // 规则中文描述
```

## 步骤 2：创建规则实现

### 文件命名

```
table_check_{规则英文描述}.go        # 实现
table_check_{规则英文描述}_test.go   # 测试
```

### 实现模板

规则实现模板参见 `coded_rules/cross_table/` 下现有规则文件，如 `table_check_drop_item_must_in_item.go`。

核心结构：
- 实现 `TableChecker` 接口（`Meta()` + `Check()`）
- `Meta()` 返回 `TableRuleMeta`，设置 `TargetSheets`（核心检查字段所在表）
- `Check()` 中加载依赖表、构建有效数据集合、遍历检查

### 加载依赖表的标准写法

```go
func (c *YourRuleCheckRule) loadDependSheet(sheetMap map[string]*excelize.File) [][]string {
    if file, sheetName, ok := check_internal.FindSheetBySuffix(sheetMap, "DependTable"); ok {
        cols, err := file.GetCols(sheetName)
        if err == nil {
            return cols
        }
    }
    return nil
}
```

`FindSheetBySuffix` 支持后缀匹配，如传入 `"DrawSkin"` 可匹配 `"皮肤抽奖|DrawSkin"`。

### 常用辅助函数

| 函数 | 用途 |
|------|------|
| `check_internal.GetColIndexByName(cols, name)` | 按列名查找列索引 |
| `check_internal.GetColValue(cols, colIdx, rowIdx)` | 获取单元格值(越界安全) |
| `check_internal.ParseIntWithError(str)` | 安全解析整数 |
| `check_internal.FindSheetBySuffix(sheetMap, suffix)` | 后缀匹配查找 Sheet |
| `check_internal.ParseCommaSeparatedIds(str)` | 解析逗号分隔的 ID 列表 |
| `check_internal.ParseItemCfg(str)` | 解析 `{id;count}` 格式的道具配置 |

## 步骤 3：注册检查器

在 `check_manager/table_check_manager.go` 的 `init()` 函数末尾添加：

```go
TableManager.Reg(json_rule.YOUR_RULE_CHECK, new(crosstable.YourRuleCheckRule))
```

## 步骤 4：配置默认规则(关键！)

在 `json_rule/default_table_rules.go` 的 `DefaultTableRules` 中，找到目标表对应的条目，将新规则追加到数组中：

```go
"SourceTable": {EXISTING_RULE_CHECK, YOUR_RULE_CHECK},
```

## 步骤 5：编写单元测试

### 测试必须覆盖的场景

| 场景 | 测试名 | 预期 |
|------|--------|------|
| 依赖数据存在且有效 | `AllValid` | `Ok=true, ErrCells=[]` |
| 依赖数据不存在(应报错) | `DependNotExist` | `Ok=false, ErrCells.Len()>=1` |
| 依赖表不存在 | `NoDependSheet` | `Ok=false, Reason 包含 "未找到"` |
| 源表中无匹配数据 | `NoMatchingData` | `Ok=true` |
| 关键列为空 | `EmptyColumn` | `Ok=true` |
| 数据格式错误(如非数字) | `InvalidFormat` | `Ok=false` |

### 测试数据构造规范

Excel 行结构：行 1-2 为空，行 3 为列名，行 4 为类型/注释，行 5 起为数据(startRowIdx=4)。

测试数据构造参见 `coded_rules/cross_table/` 下现有测试文件，如 `table_check_drop_item_must_in_item_test.go` 的 `setupTestFile`。

### 断言规范

使用 `testify/assert`，禁止 `t.Log`：

```go
assert.True(t, result.Ok, "场景描述")
assert.False(t, result.Ok, "场景描述")
assert.Len(t, result.ErrCells, 1, "应该有N个错误")
assert.Contains(t, result.ErrCells[0].Reason, "关键字", "错误信息应包含...")
assert.Contains(t, result.Reason, "未找到", "原因应包含...")
```
