# 关系链检查（CHAIN_REFERENCE）数据流模型

> 本文档描述 CHAIN_REFERENCE 规则的完整数据流模型，用于指导 JSON 配置构造、代码开发和问题排查。

## 1. 概念模型

CHAIN_REFERENCE 检查一张表（**当前表**）的某个列（**当前列**），通过两条独立的关系链（**左链/右链**）分别提取数据，然后用比较规则判断是否违规。

```
当前表(如 DrawPet) 的当前列(如 BigAward)
        │
        ├── 左链 ──→ 多步跳转 ──→ 最终值集合 L
        │
        └── 右链 ──→ 多步跳转 ──→ 最终值集合 R

比较规则(L, R, 当前列值) → 是否违规
```

### 关键区分

| | 左链 | 右链 |
|---|---|---|
| **定位** | 参考数据链 | 目标数据链 |
| **第一步数据源** | 当前表指定列（srcCol）或当前列 | 目标表全表扫描 |
| **是否依赖当前列** | 第一步取值后不再依赖 | 完全独立于当前列 |

## 2. Step 配置字段

每个步骤（ChainStep）的 JSON 配置字段参见 `json_rule/rule_def.go` 中 `ChainStep` 结构定义。

### 字段语义对照

| 字段 | 左链第一步 | 右链第一步 | 后续步骤 |
|------|-----------|-----------|---------|
| `sheet` | **强制为空**（前端自动清空） | 目标表名 | 目标表名 |
| `preCol` | **强制为空**（前端自动清空） | 用于提取 FirstStepInputValues | 用于匹配输入值 |
| `srcCol` | 当前表的取值列名 | **强制为空**（前端自动清空） | 不使用 |
| `extractCol` | 不使用（仅取值模式无提取） | 提取值传给下一步 | 提取值传给下一步 |
| `pattern`/`groups` | 对 srcCol 值做正则提取 | 不使用 | 对输入值做正则提取 |
| `filterCol`/`filterVal` | 不使用（不跨表） | 全表扫描时过滤行 | 查找时过滤行 |

## 3. ExecuteChain 执行模型

`ExecuteChain` 是单链执行引擎，被左链和右链各调用一次。实现参见 `check_internal/chain_rule_helper.go`。

### 3.1 第一步的三种模式

```
第一步判断流程:

step.SrcCol != "" ?
  ├── YES → 左链指定列取值模式
  │         从当前表 cols[srcColIdx][rowIdx] 取值作为 inputValues
  │
  └── NO → step.Sheet != "" ?
            ├── YES → 右链全表扫描模式
            │         inputValues 为空，进入全表扫描分支
            │
            └── NO  → 仅取值回退模式
                      从当前表 cols[colIdx][rowIdx] 取值
```

### 3.2 后续步骤（stepIdx >= 1）

所有后续步骤行为相同，不区分左右链：

```
上一步输出 currentValues = ["G001", "G002"]
    ↓
有 pattern? → 对每个值正则提取
    ↓
用提取/原始值构建 searchSet
    ↓
打开目标表（step.Sheet）
    ↓
有 filterCol/filterVal? → 预过滤
    ↓
遍历目标表，preCol 值在 searchSet 中的行:
  ├─ 提取 extractCol 值 → nextValues
  └─ 最后一步记录行索引（用于 CompareCol）
    ↓
nextValues 传给再下一步
```

## 4. 比较模型

Check 函数对当前列的每个单元格，分别执行左链和右链，然后比较结果。

### 4.1 单阶段比较（`chainMatchCompare` 为空）

```
leftResult.MatchValues()  vs  rightResult.MatchValues()
         ↓
compareByType(chainCompare, 左值集, 右值集) → 违规?
```

### 4.2 两阶段门控比较（`chainMatchCompare` 非空）

```
Phase 1 - 门控判断:
  leftResult.LastStepValues()   vs   rightResult.LastStepValues()
              ↓
  compareByType(chainMatchCompare, 左最后, 右最后)
  ├── 不匹配 → 跳过（两链未交汇，不报错）
  └── 匹配 → 进入 Phase 2

Phase 2 - 实际比较:
  当前列值(myColData[i])   vs   rightResult.GetFirstStepInputValues()
              ↓
  compareByType(chainCompare, [当前列值], 右链第一步preCol值集) → 违规?
```

**核心语义**：Phase 1 判断两链是否"交汇"在同一组数据上，Phase 2 比较当前列值与右链第一步提取的原始值。

### 4.3 两阶段 time_overlap 特化

当 `chainCompare="time_overlap"` 且两链都有 `compareCol` 时，使用专用的两阶段比较：
- Phase 1：Match 值交集（如武将 ID）
- Phase 2：交集项的 Compare 值（时间点）是否相同

## 5. 完整示例：结缘亭掉落检查

### 场景

检查 DrawPet 表的 BigAward 列值（如 `"{1039016;1},{1040015;1}"`）是否违反掉落规则。

### JSON 配置

```json
{
  "left": {
    "steps": [
      { "sheet": "", "preCol": "", "srcCol": "OnceDropRule" },
      { "sheet": "掉落规则表|DropRule", "preCol": "Id", "extractCol": "DropGroup" }
    ]
  },
  "right": {
    "steps": [
      { "sheet": "掉落道具表|DropItem", "preCol": "Item", "extractCol": "DropGroup" },
      { "sheet": "掉落分组表|DropGroup", "preCol": "Id", "extractCol": "Id" }
    ]
  }
}
```

参数：`chainCompare="match"`, `chainMatchCompare="match"`

### 数据流

左链：从当前行 `OnceDropRule` 取值 → 在 DropRule 表中查找 → 提取 `DropGroup`。
右链：全表扫描 DropItem → 提取 `DropGroup` → 在 DropGroup 表中查找。
两阶段比较：Phase 1 门控判断两链最后一步值是否有交集；Phase 2 比较当前列值与右链第一步 `preCol` 值集。

## 6. ChainResult 数据结构

数据结构定义参见 `check_internal/chain_rule_helper.go` 中的 `ChainResult`。

```
ChainResult {
    Values              []ChainValue   // 每个匹配行的 (Match, Compare) 对
    StepValues          [][]string     // 每步的 nextValues
    FirstStepInputValues []string      // 右链: preCol 值集 | 左链: srcCol 取值
}

便捷方法:
  .MatchValues()              → Values[].Match（= LastStepValues）
  .LastStepValues()           → StepValues 最后一个
  .FirstStepValues()          → StepValues[0]
  .GetFirstStepInputValues()  → FirstStepInputValues（Phase 2 右侧值）
  .GetCompareValues(key)      → 指定 Match 键对应的 Compare 值
```

### FirstStepInputValues 的含义

| 链 | 含义 |
|----|------|
| 左链 | srcCol 取值（正则提取后） |
| 右链 | 全表扫描时收集的 preCol 值集 |

在两阶段门控比较的 Phase 2 中，右链的 `FirstStepInputValues` 与当前列值比较。

## 7. 前端序列化规则

`serializeSteps` 函数在保存时自动清理第一步字段：

| 字段 | 左链第一步 | 右链第一步 |
|------|-----------|-----------|
| `sheet` | 强制清空 | 保留用户配置 |
| `preCol` | 强制清空 | 保留用户配置 |
| `srcCol` | 保留用户配置 | **强制清空** |

## 9. 排错指南

### "未找到源列: XXX"

**原因**：ExecuteChain 第一步 `srcCol` 非空，但在当前表中找不到该列名。
**检查**：
- 左链第一步的 srcCol 值是否是当前表中实际存在的列名
- 右链第一步不应该有 srcCol（前端应自动清空）

### "目标表不存在: XXX"

**原因**：step.Sheet 指定的表不在 sheetMap 中。
**检查**：
- sheetMap 是否包含该表（检查 filterSheetMapByRules 过滤逻辑）
- 表名是否拼写正确，是否需要中文前缀（如 "掉落规则表|DropRule"）

### 检查永远返回成功

**可能原因**：
1. 左链 FirstStepInputValues 为空 → srcCol 列值为空或 srcCol 配置错误
2. 右链全表扫描无结果 → 目标表数据为空或过滤条件过滤掉了所有行
3. 两阶段门控 Phase 1 不通过 → 两链最后一步值无交集
