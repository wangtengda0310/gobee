# 规则重构 - 拆分增删改通知规则（已完成）

## 重构目标

将 `NEW_ROW_NOTIFY`（新增行+删除行+新增列+删除列）和 `ROW_CHANGE_NOTIFY`（修改行）拆分为 5 个独立规则，遵循单一职责原则。

## 完成状态

✅ **已完成** — 所有规则已开发、测试通过并合并。

| 新规则 | 功能 | 文件 |
|--------|------|------|
| `ADDED_ROW_NOTIFY` | 新增行通知 | `table_check_added_row_notify.go` |
| `REMOVED_ROW_NOTIFY` | 删除行通知 | `table_check_removed_row_notify.go` |
| `MODIFIED_ROW_NOTIFY` | 修改行通知 | `table_check_modified_row_notify.go` |
| `ADDED_COL_NOTIFY` | 新增列通知 | `table_check_added_col_notify.go` |
| `REMOVED_COL_NOTIFY` | 删除列通知 | `table_check_removed_col_notify.go` |

旧规则 `NEW_ROW_NOTIFY` / `ROW_CHANGE_NOTIFY` 保留为废弃组合规则，向后兼容。

## 关键设计决策

### 性能优化 — Diff 缓存层

拆分为 5 个规则后，引入 `CheckParam.DiffResult` 缓存字段避免重复 Git 操作。第一个规则执行差异检测后缓存结果，后续规则复用。详见 `xlsx/check_internal/diff_cache.go` 的 `GetOrDetectDiff`。

### 向后兼容

- 旧枚举保留，标记为 `Deprecated`
- 旧规则委托到新规则实现
- 提供 3 个版本的迁移窗口期

## 迁移指南

### 旧配置 → 新配置

**旧配置**（使用 `NEW_ROW_NOTIFY`）：
```json
{
  "type": "NEW_ROW_NOTIFY",
  "params": {
    "idColName": "Id",
    "notifyAddedRows": "true",
    "notifyRemovedRows": "true"
  }
}
```

**等效新配置**：
```json
[
  {"type": "ADDED_ROW_NOTIFY", "params": {"idColName": "Id"}},
  {"type": "REMOVED_ROW_NOTIFY", "params": {"idColName": "Id"}}
]
```
