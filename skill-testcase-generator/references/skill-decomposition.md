# 技能拆解逻辑（规则参考）

> **本文件的角色**：这是"怎么把一个技能拆成测试点"的**规则/逻辑**，所有技能通用、可被反复复用。
> - **不含数据**：不存牌层级、术语定义等任何具体数据（那些是现读或别的快照）。
> - **不存结果**：不保存任何技能拆完的产物；某个技能的拆解结果每轮写进 `overview.json` 的「技能定义拆解映射表」section（见 `overview-format.md`）。
> - **调用时机**：阶段一拆解技能定义 → 5 模块；阶段三按模块生成用例。
> 模块清单本身见 [skill-test-point-modules.md](skill-test-point-modules.md)；本文件只讲技能定义模块下的拆解规则。

**核心流程（三步流水线）**：

```
§1 拆原子项（找轴）
  → §2 给每个原子项定模块（可双归类）
    → §3 在每个「原子项 × 模块」上，按该模块的规则展开成用例
```

§4 节点拆分是另一条 track（服务技能封禁/被重置/被删除/被转移的「发动期间」，非技能定义 5 模块）。
**顺序不能反**：§3 展开规则因模块而异（见各模块小节），不先定模块就无法正确展开。

## 0. 总纲与逐条目原则

源文档对「技能定义」模块的纲领（测试用例生成点 sheet 中「技能定义」的解释）：
> 「将技能描述拆解成一个个术语或者机制定义，针对每个拆解项去关联文档中的内容，罗列测试点。」

- **逐条目拆解**：一个技能可能有多个条目（C 列合并范围内多行，见 [sheet-structure.md](sheet-structure.md)）。**每个条目各自走一遍完整拆解**。
- **主动 / 被动分开**：主动条目与被动条目是不同情况，分别拆解、分别生成用例，不混在一起。
- **被授予技能（sub_skills）单独处理**：若被测技能文案授予另一独立技能（如天时「所有角色获得归心」），该被授予技能记入 overview `sub_skills`（识别规则见 `SKILL.md` 1.2）。在被测技能里，「授予 X」只作为一个**发动效果原子项**：测授予对象是否正确、被授予后 X 是否按其文案定义生效、以及被测技能本身被重置 / 被删除 / 被转移时已授予 X 的去留（结算不确定写「需游戏内验证」）。**不**在被测技能运行里把 X 自身完整拆原子项展开——那是 X 作为被测技能单独跑时的工作。

> 三个易混概念：**条目（entries）** = 同一技能名 C 列合并的多行；**被授予技能（sub_skills）** = 文案授予的另一技能；**关联技能** = 场上其它技能与被测的交互（见 [associated-skill-interaction.md](associated-skill-interaction.md)）。三者各自处理、互不混入对方集合。

## 1. 拆原子项（找轴，带 ID）

把每个条目的文案拆成最小的、能独立成为一个测试维度的**原子项**——即后面 §3 要逐个枚举取值的"轴"。

**示例**：「出 1 张红色手牌」→ `[出] [1张] [红色] [手牌]` 共 4 个原子项。

- **能独立成测试角度就拆开**（数量、颜色、区域、动作各是一维）；不可再分则停。
- 每个原子项分配一个 **ID**（`拆-01`、`拆-02`…），用于阶段三完整性校验精确追踪（不靠脆弱的文本匹配）。

**动作/机制类原子项 → 规范术语（必读）**：文案里的动作（打出、当作X、转化、摸、弃置、获得、限X次…）要对应到「基本术语」的三组**动作词汇表**——「牌与牌堆操作」「卡牌使用与效果」「技能机制与能力变化」（行范围见 `sheet-structure.md`，运行时现读）。这些术语名是**参数化/占位形式**（如「当xx牌」「转化牌」「每个出牌阶段限次」），而文案是具体形态（「当作杀」「出牌阶段限1次」），**不能靠术语名字面搜**——读术语**定义**、按语义判断文案动作落在哪个。匹配到的术语即该原子项的「关联文档/来源」，其定义并入核心术语。

> 「技能机制与能力变化」组特别说明：限定 / 每轮 / 每回合 / 你的回合 / 每个出牌阶段限次 → 喂「重置时机」二级模块（见 §3）；获得 / 失去废除 / 转移 / 复制刻写 / 重置技能进词表；「羁绊武将」「技能类型」是定义/分类、非动作，不参与映射。

> 易混区分（不分清就会测错机制）：
> - **当xx牌**（原牌不变，仅当作另一张牌使用/打出）≠ **转化牌**（原牌消失、变成新牌）。如武圣义绝「将任意牌当作杀打出」属当xx牌。
> - **摸牌**（从牌堆顶摸）≠ **获得牌**（将某张牌加入手牌/装备区）。
> - **销毁牌** ≠ **烧毁牌**（定义注明「效果一致但机制不是同一个」）；弃置牌 ≠ 移出牌 ≠ 销毁/烧毁。
> - **限次四档作用域不同**：每轮限次（全场每轮）≠ 每回合限次（任何人回合）≠ 你的回合限次（仅你回合）≠ 每个出牌阶段限次（插入的出牌阶段独立重新计数、原阶段计数不变）；限定 = 每局1次、可被重置。

> **拿不准就标注**：动作词归属两个术语都可能命中、判不准时，不静默二选一——在拆解映射表「关联文档/来源」列标 `待确认：X 或 Y`，按更可能者生成用例。

## 2. 给每个原子项定模块

把每个原子项归到 5 个二级模块之一；一个原子项可能产生**多条测试义务**（见下方双归类）。

| 模块 | 含义 | 归类依据 |
|------|------|---------|
| **发动阶段** | **时间维度**：在哪个时间点/阶段可发起 | 每个条目永远遍历「技能发动阶段」16 节点（详见 §3 发动阶段） |
| **发动条件** | **规则维度**：除时间外还需满足的前提/事件/状态（含代价的**前提**） | 关联事件/状态/数值/资源类术语 |
| **发动方式** | 怎么发起（细到每个效果段） | E 列（主/被）+ 文案"你可以" |
| **发动效果** | 发起后做什么（含代价的**执行**与数量边界） | 关联动作/伤害/牌堆类术语 |
| **重置时机** | 用过后何时能再用 | 文案的限次表达 |

**边界裁定**（拆错模块是最常见的失误）：
- **发动条件 vs 发动效果**（用反向查表的术语大类判）：事件/状态/数值/资源类**前提** → **发动条件**；动作/伤害/牌堆类（执行动作）→ **发动效果**。例：「受伤」是触发前提 → 发动条件；「打出杀」是执行 → 发动效果。
- **双归类**：一个原子项可同时落在两个模块（典型：代价），此时**算作两个测试义务、各分配一个 ID**，两处都生成内容。例：「弃置 1~2 张牌」作为代价 → 前提「有牌可弃」归**发动条件**；执行 + 数量边界（弃 0/1/2/超出）归**发动效果**。
- **发动方式来源是 E 列，不是触发词**。「受伤」是触发条件，只进**发动条件**，不进发动方式。

## 3. 各模块怎么展开成用例

每个原子项归好模块后，按其所属模块的规则展开成正/反/边界用例——**展开方式因模块而异**。
> 5 个模块里，无限次时只跳过**重置时机**；其余 4 个都不跳——无限制时"无限制本身"也是测试角度（如"任意阶段都触发"）。

### 发动阶段

**遍历**：永远现读「基本术语」sheet「技能发动阶段」大类（A23:A38，16 节点）、逐节点生成用例。

**时机词定义**：时机词**只能来自「技能发动阶段」大类**（基本术语 A23:A38），例如：能对应大类节点的词（出牌阶段 / 摸牌阶段 / 弃牌阶段 / 回合开始时 / 回合结束时 / 每轮…），或回合结构表达（`限X次` / `每回合` / `你的回合` / `别人的回合`）。
文案中其他大类的术语不算时机词、按大类归位：
- 「角色状态与生命周期」（A39:A57）：登场 / 受伤 / 阵亡 / 复活 / 体力值变化 等 → **发动条件**（事件触发）
- 「卡牌使用与效果」/「牌与牌堆操作」（A58:A86）：打出装备牌时 / 摸牌后 / 弃置牌后 等 → **发动条件**（动作前提）
- 句型 `当…时` / `…时` / `…后` 引出的任何动作或状态都是事件触发，不是时机词

**归属者展开**：仅当文案**既有时机词又有归属者修饰**时触发，**仅在命中节点位置**展开。归属者集合按文案上下文决定（常见 {其他角色的, 你的} 二元；文案更细则按文案出现的所有情况展开，如 {敌方的, 友方的, 自己的}）。不命中节点不展开。

**预期判定**：

| 文案情况 | 命中节点 + 命中归属者 | 命中节点 + 不命中归属者 | 不命中节点 |
|---|---|---|---|
| 无时机词 | 全 16 节点 → 可发动 | — | — |
| 有时机词、无归属者 | 可发动 | — | 不可发动 |
| 有时机词 + 归属者 | 可发动 | **不可发动** | 不可发动 |

**用例 8 列里只规定 3 列**：

| 列 | 填什么 |
|---|---|
| 一级模块 | `发动阶段` |
| 二级模块 | 该用例对应的节点名；归属者展开行则带归属者前缀全称，如 `其他角色的回合开始时` / `你的回合开始时` |
| 拆解项 | `拆-NN`，同一条目发动阶段用例共用一个 ID |

其余 5 列（标题/前置/步骤/预期）由模型按语义撰写。

**总条数**：
- 无时机词 / 有时机词无归属者 → 16 条
- 有时机词 + 归属者 → (16 − 命中节点数) + (命中节点数 × 归属者情况数)

**禁令**：
- 禁止注入游戏常识（"主动技需在出牌阶段"等理由判不可发动是错的）
- 发动阶段下不得出现牌/事件枚举（如装备牌子类型）
- **二级模块列只填节点名**（如`选将阶段`、`其他角色的回合开始时`、`你的回合开始时`），**严禁附加任何前缀或注解**：不写 atom 名拼接（`发动时机（任意）→选将阶段`）、不写正反标签（`（正向）` / `（反向：你的）`）。即便命中归属者行的节点名与 atom 名同字（如 atom=`其他角色的回合开始时`、二级模块=`其他角色的回合开始时`），也保持原样、不加注解；正反由"预期"列的"可发动/不可发动"自然区分。

**worked examples**：
- 武圣义绝「你可以将任意牌当作杀打出」无时机词 → 全 16 条预期"可发动"
- 入蜀三策「其他角色的回合开始时…」时机词=回合开始时、归属者={其他角色的, 你的} → 15 不命中节点(不可发动) + 命中节点展开 2 条：`其他角色的回合开始时`(可发动) + `你的回合开始时`(不可发动) = 17 条
- 锦狮子「当你打出装备牌时…」"当…时"是事件触发归发动条件 → 发动阶段视作无时机词，全 16 条预期"可发动"

### 发动条件
只管**规则维度**：去除时间约束后还需满足哪些玩法/规则前提才能发动（时间约束归发动阶段，不在此重复）。展开：满足 → 可发动 / 不满足 → 不可发动 / 临界边界（如前提"手牌≥2"→ 测 1 / 2 / 3）。代价的"前提"（有牌可弃）也在此测。

### 发动方式
- **E 列有值 → 直接采信**（权威）。
- **E 列为空 → 按文案推断主/被动**，并在用例标注 `[发动方式：源文档未填写，按文案推断为 X，待项目组更新后核实]`：
  - 含「出牌阶段限 X 次」+「你可以」且无外部触发时机 → **主动**
  - 含触发时机词（回合开始时 / 受伤 / 打出杀时 / 其他角色…时 / 损失体力）→ **被动**
- **细到每个效果段**：同一被动技不同段的发动方式可能不同（如"获得牌"自动 +"立即打出"可选）。
- **被动自动 vs 弹窗**：文案含「你可以」→ 被动可选（测确认/取消）；无 → 被动默认自动（即结算）。

> 快照检测到 sheet 变化后重跑，PM 补完的真实 E 值会自动替换上面的推断标注。

### 发动效果
变化最丰富，是广覆盖的核心。对每个动作/效果原子项，沿**相关**维度展开正反用例（只展相关维度，不机械套全表）：

| 维度 | 展开示例 |
|------|---------|
| 牌类型 | 行动牌/战法牌/装备牌/无类型；任意牌→全枚举（见下「牌枚举」）；具体牌名→不展开 |
| 牌的状态 | 普通/强化/复制/带标记 |
| 目标条件 | 自身/友方/敌方/特定身份/特定状态 |
| 距离 | 距离1/距离≤X/无距离限制 |
| 状态条件 | 目标是否被封禁/连环/重伤/虚弱 等 |
| 伤害类型 | 普通/火焰/雷电/无属性 |
| 数量边界 | 0/1/上限/超出 |

**牌枚举**（牌类型维度的专项展开）：
- 数据来源：**牌类型层级快照**（10 个叶子类型，见 `sheet-structure.md`「牌类型层级快照」），直接遍历，不在此现场去重。
- 触发范围不限于「任意/所有/每种/任何」，扩大到**所有牌相关原子项**：

| 文案表达 | 展开规则 |
|---------|---------|
| 杀、闪、桃 等具体牌名 | **不展开**（已最小粒度）；杀/火杀/雷杀 按伤害类型维度处理（见上方维度表），不计入牌枚举 |
| 「一张牌」「任意牌」「某张牌」 | 遍历快照全部 10 个叶子类型 |
| 「战法牌」 | 遍历快照中战法牌的 5 个叶子（普通战法牌/卜卦牌/锦囊妙计专属战法牌/六出奇计专属战法牌/圯桥授书专属战法牌） |
| 「装备牌」 | 遍历快照中装备牌的 3 个叶子（武器牌/防具牌/坐骑牌） |
| 「红色手牌」等带修饰 | 颜色枚举 × 区域枚举 |

- **硬要求**：每个叶子类型单独一条正向用例，不合并——每个都是独立测试维度，这是覆盖度的关键。
- **粒度边界**：枚举即遍历快照的叶子类型（约 10 个），**绝不展到 A 列具体牌名**（如「坐骑牌-赤兔」「行动牌-杀」）。快照里没有的牌名不是枚举维度。

### 重置时机
只测技能**自身**的恢复规则。文案的限次表达对应动作词表的限次术语（限定 / 每轮 / 每回合 / 你的回合 / 每个出牌阶段限次，§1 已按定义匹配），其**作用域决定恢复时机**：达上限禁用 / 对应作用域刷新时恢复（如"每个出牌阶段限次"在新出牌阶段恢复、且插入的出牌阶段独立计数）/ 限定技本局不恢复（但可被重置）。技能无限次描述时**跳过**（不生成空用例）。
> 外部事件导致的计数清除不在此测，避免与一级模块重复：涅槃/复活/再战归「武将重新初始化」，强制重置归「技能被重置」。

## 4. 节点拆分（独立 track：服务"发动期间每节点插入"）

> 本节不属于技能定义 5 模块流水线，服务的是技能封禁/被重置/被删除/被转移这 4 个一级模块的「发动期间」二级模块（见 `skill-test-point-modules.md`）。

要测"技能流程中每个节点被插入 X"，必先把技能流程切成有序节点。

**为什么**：技能分步结算，中途打断常引发缺陷（代价已付效果未生效、效果做一半、计数已记）。

**时间轴模型**：
```
[发动声明/触发] → ●步骤1(代价) → ●步骤2 → … → [结算完成]
   发动前X 测可用性    ↑发动期间X(每节点各1条)        发动后X 测已生效效果去留
```

规则：
- **节点粒度**：不可分的单步不再拆（"摸 2 张牌" = 1 节点）。节点边界 = **一次可观测的游戏状态变更**。
- **复用既有拆解**：节点序列直接采用 §3「发动效果」拆出的有序步骤，不重复拆分。
- **4 模块共用同一套节点序列**（一次拆解），各自按语义写预期。
- **全覆盖**：N 个内部节点 → 每模块生成 N 条"发动期间"用例，不取代表性。

> 注意区分「重置时机」（§3，技能自身限次的自然恢复）与「技能被重置」（独立模块，外部强制重置干扰）——两者平行，一个看自己，一个看外部。
