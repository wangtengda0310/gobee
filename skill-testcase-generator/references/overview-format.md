# overview.json — 测试概览格式

阶段二生成，是 `generate_outputs.py` 的输入之一。承载阶段一采集与拆解的全部结果，供阶段三生成用例、完整性校验追踪。

## 顶层结构

```json
{
  "title": "名将杀技能测试概览",
  "skill_name": "枪出如龙",
  "hero": "赵云",
  "faction": "蜀汉",
  "skill_category": "武将技",
  "entries": [
    {"entry_id": "条目1", "发动方式": "被动触发", "文案": "出杀，摸1张牌；出杀：打出杀时"},
    {"entry_id": "条目2", "发动方式": "主动使用", "文案": "你的闪可以当作杀打出。"}
  ],
  "sub_skills": [
    {"子技能名称": "归心", "子技能文案": "..."}
  ],
  "sections": [ ... ]
}
```

| 字段 | 必需 | 说明 |
|------|------|------|
| `title` | 是 | 固定「名将杀技能测试概览」 |
| `skill_name` | 是 | 技能名称 |
| `hero` | 是 | 归属武将；按合并单元格判定，真未合并填「未标注」 |
| `faction` | 否 | 武将势力（B 列合并范围值） |
| `skill_category` | 否 | 技能分类（D 列） |
| `entries` | 是 | **C 列合并范围内全部条目**。每条目 `{entry_id, 发动方式, 文案}`；`文案` 完整照搬原文。单条目技能也是长度 1 的数组 |
| `sub_skills` | 否 | 技能授予的另一独立技能（如天时→归心），与 entries 是不同概念；无则省略或传 `[]` |
| `sections` | 是 | 小节数组，见下 |

> `entries`（同一技能名的多个条目）与 `sub_skills`（被授予的另一技能）不要混淆。条目与子技能处理、发动方式判定见 [skill-decomposition.md](skill-decomposition.md)。

## sections 通用结构

每个 section：`{"heading": 小节标题, "columns": [列名…], "rows": [[单元格…]…]}`，每行长度 = columns 长度。脚本渲染顺序：标题行 → 列头行（白字蓝底）→ 数据行（逐行带边框）。

> 任何 section 中，被引用概念若在 1.2 判定为「源文档未收录」（重要但查不到、无法推断），其 `原文定义` / `定义来源` 列写 `⚠️ 源文档未收录` + 一句可能含义。

阶段二固定写入以下 6 个 section：

### 1. 技能定义拆解映射表

`columns: ["拆解项ID", "所属条目", "原子项", "归入二级模块", "关联文档/来源"]`

阶段一 1.3 拆解的产物落表，是阶段三完整性校验的追踪依据。**行/列语义**：

- **每行 = 一个测试义务**（原子项 × 归入模块）。一个双归类的原子项（如代价「弃置1~2张牌」）在拆解时已算作两个测试义务、各一个 ID（见 skill-decomposition.md §2），因此自然占两行。
- **拆解项ID**：`拆-01`、`拆-02`…，用例的「拆解项」列回填此 ID 供精确追踪。
- **所属条目**：该原子项来自哪个条目（`条目1`/`条目2`）。
- **归入二级模块**：发动阶段 / 发动条件 / 发动方式 / 发动效果 / 重置时机 之一。**在用例表中此模块名落到「一级模块」列、本行原子项落到「二级模块」列**（列映射见 `testcase-format.md`）。
- **关联文档/来源**：原子项关联到的术语/牌/机制定义出处；查不到则填「文档未收录」，仍照常生成用例（口径同 [test-point-knowledge.md](test-point-knowledge.md)）。

### 2. 概念范围枚举

`columns: ["宽泛概念", "子类型", "定义来源"]`

牌大类→小类、非牌宽泛概念（伤害类型/区域/状态效果等）、以及**发动阶段的节点遍历**合并在一张表，每行一个子类型，**与阶段三用例 1:1 对应**。`宽泛概念` 列由模型按文案自由命名（无格式包装规则），`子类型` 列填该行对应用例的「二级模块」值。

发动阶段部分：表行数 = 发动阶段用例条数（详见 `skill-decomposition.md` §3 总条数）；`子类型` 列即各用例「二级模块」值的镜像，命中节点归属者展开行则是带归属者前缀的完整节点名。

```json
{
  "heading": "概念范围枚举",
  "columns": ["宽泛概念", "子类型", "定义来源"],
  "rows": [
    ["任意牌", "行动牌", "牌 sheet B/C 列"],
    ["任意伤害类型", "火焰伤害", "基本术语 状态效果与属性标签"],
    ["其他角色的回合开始时", "选将阶段", "基本术语 技能发动阶段"],
    ["其他角色的回合开始时", "其他角色的回合开始时", "基本术语 技能发动阶段"],
    ["其他角色的回合开始时", "你的回合开始时", "基本术语 技能发动阶段"]
  ]
}
```

### 3. 核心术语

`columns: ["术语", "分类", "原文定义", "来源"]`

1.2 反向查表命中的术语，按所属大类分类。`原文定义` 完整照搬，`来源` 记坐标（格式如 `基本术语 cFEl74 C<行号>`）。

### 4. 机制测试点

`columns: ["机制主题", "预设测试点"]`

**常驻 section**（不论是否引用到机制都输出，便于在概览中显示"机制 sheet 已检索过"，避免沉默跳过的假象）。
- **技能引用了机制主题**：1.2 反查命中的每个机制主题下的每条预设测试点占一行。`机制主题` 填源表 A 列原文（如「受伤的机制测试点」）；`预设测试点` 填该条预设的原文内容。每条预设在阶段三末段生成一条独立用例（见 `SKILL.md` 3.4）。
- **未引用任何机制主题**：仍输出本 section，但只一行占位（把已检索过的主题清单写在「机制主题」列，便于人工核对）：`["本次未引用任何机制主题（已检索：受伤的机制测试点 / 回复体力的机制测试点 / 每轮开始的机制测试点）", "—"]`。检索清单运行时现读「所有机制」sheet A 列填入。

### 5. 关联技能（辅助模块）

`columns: ["技能名称", "原文", "关联类型", "组合路径分析", "来源"]`

1.4 去重集合中的关联技能，每行一个。`关联类型` 填交互类型标签（同武将多技能联动 / 同技能多条目联动 / 状态叠加 / 同时机 / 同条件，不写 L1/L2 内部代号）；`组合路径分析` 描述如何与被测技能配合（规则与标签定义见 [associated-skill-interaction.md](associated-skill-interaction.md)）。

### 6. 测试点背景知识

`columns: ["实体/术语", "类型", "原文定义", "来源"]`

从 `test-point-knowledge.md` 提取本技能相关的机制术语定义（封禁/重置/删除/转移/刻写/复制/涅槃/再战/复活…），供阶段三撰写预期结果时照搬。`类型` 如「机制定义」。查不到的概念按 test-point-knowledge.md「表外概念」口径处理。
