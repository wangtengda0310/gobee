# testcases.json — 测试用例格式

阶段三生成，是 `generate_outputs.py` 的输入之一。

## JSON 结构

```json
{
  "columns": ["编号", "一级模块", "二级模块", "拆解项", "标题", "前置条件", "步骤", "预期结果"],
  "rows": [
    ["TC-01", "发动效果", "摸1张牌", "拆-03", "出杀后摸1张牌", "...", "...", "..."]
  ]
}
```

## 8 列约定（顺序不可变，镜像源表测试点结构）

| # | 列名 | 说明 |
|---|------|------|
| 1 | 编号 | `TC-01`、`TC-02`… 全局连续 |
| 2 | 一级模块 | 对齐源表「测试点模块」。**技能定义例外**：其 5 个子模块（发动阶段/发动条件/发动方式/发动效果/重置时机）**直接作为一级模块**填此列，便于看清用例针对哪个点；其余模块（技能封禁/被重置/…）填模块名本身。清单以 [skill-test-point-modules.md](skill-test-point-modules.md) 当前快照为准，**不硬编码** |
| 3 | 二级模块 | **技能定义类**：填该用例针对的**原子项**（发动阶段枚举用例填对应时间节点）；其余模块对齐源表「测试点二级模块」（如 发动期间被封禁）；关联技能交互模块填交互类型标签 |
| 4 | 拆解项 | 技能定义类用例填原子项 ID（`拆-01`…，供完整性校验追踪，与第 3 列原子项对应）；其他模块填二级模块路径或留空 |
| 5 | 标题 | 一句简短描述 |
| 6 | 前置条件 | 触发前的状态/设置 |
| 7 | 步骤 | 操作步骤（可多行） |
| 8 | 预期结果 | 期望的输出/行为，撰写规范见下 |

Excel 按「一级模块 → 二级模块」自然分组，与源表同构。

## 模块取值来源

- **技能定义**的 5 个子模块（输出中作为一级模块，见第 2 列说明）的拆解与维度展开规则见 [skill-decomposition.md](skill-decomposition.md)。
- **其余一级模块**（封禁/被重置/被删除/被转移/刻写复制/多个同时在场/重新初始化/断线重连）逐个生成，封禁等 4 个模块的「发动期间」按节点序列每节点各一条。
- **关联技能交互**为辅助模块，二级模块/标题标交互类型，规则见 [associated-skill-interaction.md](associated-skill-interaction.md)。

## 预期结果撰写原则

> 引用**外部定义**（机制/牌/其他技能——不在被测技能条目文案内的东西）时，照搬该定义原文 + 标来源（机制定义从 [test-point-knowledge.md](test-point-knowledge.md) 取，别凭记忆），再写预期行为；结算不确定就写「需游戏内验证」。

- 测技能自身、信息已足够 → 直接写具体预期，不必引用、不啰嗦。例：「重连后 buff 图标在 2 秒内重新出现并保持原剩余轮数」即合格。
- 引用外部定义时才照搬原文，避免幻觉。照搬格式：「<术语>：<定义原文> [来源：<sheet 名> <sheet_id> <单元格>]」。先照搬这样一条，再写被测技能在该定义下的具体表现；不要只写「与封禁正常交互」这类笼统结论。
- 结算顺序、中断回滚等无法仅凭文案推断的，如实写「…需游戏内验证」，不编造。
- 外部实体在源文档查不到定义时，写 `[来源：源文档未收录，待人工补充]`。

## 自动样式（脚本处理）

- 列宽按 8 列设置；Sheet 2 自动筛选 + 冻结首行。
- 中文文本内引号用「」，不用 ASCII `"`，否则 JSON 解析失败。
