# 前端调试方法

rain-qa-func 是 Wails v3 桌面应用，前端嵌入在 WebView2 中。本文档整理了查看和操控前端页面的所有方法。
调试前查看[前端布局文档](../frontend/docs/layout)了解一下前端页面

## 架构背景

```
┌─────────────────────────────────────────────┐
│  Wails App 模式                             │
│                                             │
│  WebView ←── Wails Bridge ──→ Go Backend    │
│  (前端)     (IPC 通信通道)     (文件/服务)    │
│                                             │
│  @wailsio/runtime.Call.ByID(methodID)       │
│     → 通过 Bridge 传到 Go 后端执行           │
└─────────────────────────────────────────────┘
```

前端通过 `@wailsio/runtime` 的 `Call.ByID()` 调用 Go 后端方法，通过 `Events.On/Emit` 进行事件通信。**浏览器直接访问 Vite dev server 时 Bridge 不存在**，所有后端调用都会失败，因此需要在 WebView2 环境中调试。

## 方案对比

| 维度 | DevTools | 远程调试 | Playwright 脚本 |
|------|----------|---------|-----------------|
| 需要改代码 | 不需要 | 不需要（环境变量） | 不需要（环境变量） |
| 自动化能力 | 无（纯手动） | 有限 | 完整 |
| AI 可操控 | 否 | 否 | 是（通过 cdp-debug.js） |
| Wails Bridge | 正常 | 正常 | 正常 |
| 适合场景 | 日常手动调试 | 跨浏览器调试 | 自动化测试/AI 操控 |

## 方案一：内置 DevTools（零配置）

代码中已设置 `DevToolsEnabled: true`（`main.go`），远程调试端口通过 `getCDPPort()` 从 `CDP_PORT` 环境变量读取（默认 9223）。

**使用**：在应用窗口中 **右键 → 检查元素**，打开完整的 Chrome DevTools。

**实测结果（2026-04-01）**：✅ 可用。在 `wails3 dev` 启动的窗口中右键即可打开 DevTools 面板。

**能力**：Elements、Console、Network、Sources、Performance 等全部面板可用。

**限制**：
- 仅 `wails3 dev` 或带 `-tags devtools` 构建时可用
- `wails3 task build`（production build tag）会强制禁用
- 纯手动操作，无法自动化

## 方案二：Chrome Remote Debugging（零配置）

Wails3 的 `application.WindowsOptions` 支持传递 WebView2 浏览器参数。代码中已通过 `getCDPPort()` 函数自动配置。

### 端口配置

通过环境变量 `CDP_PORT` 指定端口，默认 `9223`：

```bash
# 默认端口 9223
wails3 dev

# 多 worktree 并行时使用不同端口
CDP_PORT=9224 wails3 dev
```

实现代码（`main.go`）：
```go
func getCDPPort() string {
    port := os.Getenv("CDP_PORT")
    if port == "" { port = "9223" }
    // ... 数字校验 ...
    return port
}
```

**原理**：`AdditionalBrowserArgs` 通过 go-webview2 库设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量，在 WebView2 环境创建前生效。

**注意**：WebView2 共享单一浏览器进程，browser args 对所有窗口全局生效。

### 验证

```bash
# 检查端口是否监听（替换为实际使用的端口）
netstat -ano | grep 9223

# 查看可用页面目标
curl http://localhost:9223/json/list
```

### 连接方式

- **Chrome 浏览器**：打开 `chrome://inspect`，配置 Target: `localhost:9223`
- **直接访问**：`http://localhost:9223/json/list` 获取 WebSocket URL，用于 CDP 连接

**实测结果（2026-04-01）**：✅ 完全可用。

默认端口 9223（避免与 Edge 的 9222 冲突），配置见 `main.go` 中的 `getCDPPort()` 函数。

CDP 端点返回示例：
```json
{
   "Browser": "Edg/146.0.3856.84",
   "title": "Wails + Vue + TS",
   "url": "http://wails.localhost:9245/",
   "webSocketDebuggerUrl": "ws://localhost:9223/devtools/page/..."
}
```

> 注：`url` 是 WebView2 内部页面地址（由 Vite dev server 提供），`webSocketDebuggerUrl` 是 CDP 调试连接地址。两者端口不同，用途不同。

## 方案三：Playwright 脚本附加 WebView2

通过 CDP 协议连接运行中的 WebView2 实例，**需要先启用方案二的远程调试端口**。

### 前提

1. rain-qa-func 正在运行（CDP 端口已通过 `CDP_PORT` 环境变量或默认 9223 启用）

### Playwright 脚本

```javascript
const { chromium } = require('playwright');

// 端口对应 CDP_PORT 环境变量值（默认 9223）
const browser = await chromium.connectOverCDP('http://127.0.0.1:9223');
const context = browser.contexts()[0];
const page = context.pages()[0];

// 完整的 Playwright API 可用
await page.screenshot({ path: 'app.png' });
await page.click('button');
const content = await page.content();
```

### cdp-debug.js CLI 工具（推荐）

项目提供了 `scripts/cdp-debug.js` 脚本，通过命令行直接操作 WebView2，无需 MCP 插件：

```bash
# 截图（--port 指定 CDP 端口，默认 9223）
node scripts/cdp-debug.js screenshot [path] --port 9223

# 执行 JS 表达式
node scripts/cdp-debug.js evaluate "document.title" --port 9223

# 点击元素
node scripts/cdp-debug.js click "button.settings" --port 9223

# 输出可访问性树
node scripts/cdp-debug.js snapshot --port 9223

# 返回当前 URL
node scripts/cdp-debug.js url --port 9223
```

> 多 worktree 并行时，每个实例使用不同 `CDP_PORT`，脚本通过 `--port` 匹配对应端口。

### 为什么不使用 Playwright MCP 插件

Playwright MCP 插件（`@playwright/mcp`）默认启动独立浏览器，`--cdp-endpoint` 参数虽可连接已有实例，但 MCP 配置是全局的——多个 Claude Code 会话共享同一配置，无法区分不同 worktree 的端口。因此使用独立脚本更灵活。

**实测结果（2026-04-01）**：✅ 完全可用。测试验证了以下能力：

| 测试项 | 结果 |
|--------|------|
| CDP 连接 | ✅ 成功连接到 WebView2 |
| 页面截图 | ✅ 成功捕获完整界面 |
| DOM 读取 | ✅ 可读取 192114 字符 HTML |
| 导航按钮识别 | ✅ 识别到 11 个按钮（设置、AI助手、战斗测试等） |
| 点击交互 | ✅ 点击"配表测试"按钮成功切换页面 |
| Wails Bridge | ✅ Go 后端调用正常（在 WebView2 环境中） |
| `window.__wails__` 检测 | ⚠️ JavaScript 中不可直接检测（Wails Bridge 是原生层实现，非 JS 全局变量） |

## 方案四：浏览器直接访问 Vite Dev Server（不推荐）

`wails3 dev` 启动的 Vite dev server 可直接访问，但**Wails Bridge 不存在**，所有 Go 后端调用（`Call.ByID()`、文件操作、事件监听）都会失败。**仅限查看纯前端页面，不能执行实际功能**。

## 方案五：直接阅读前端源码

源码位于 `frontend/src/`，组件结构清晰。注意路由使用 `createMemoryHistory()`（非 Web History），E2E 测试需通过点击导航而非 URL。详见 [e2e-sync-rules.md](../frontend/docs/e2e-sync-rules.md)。

## 构建模式对 DevTools 的影响

| 构建命令 | DevTools UI | 远程调试 |

## CDP 调试工具

| 脚本 | 用途 | 使用方式 |
|------|------|---------|
| `scripts/cdp-debug.js` | 通用 CLI 工具，支持截图、执行 JS、点击、快照、获取 URL | `node scripts/cdp-debug.js <command> --port <port>` |
| `rain-qa-func/cdp-check.js` | 一次性诊断脚本，检查前端组件挂载状态和劫持通知 | `node rain-qa-func/cdp-check.js` |

### CDP 操作要点

| 场景 | 要点 |
|------|------|
| Naive UI Modal 遮罩层 | Playwright `page.click()` 会被 `.n-modal-mask` 阻挡，使用 `evaluate` 执行 JS `element.click()` 绕过 |
| Select 下拉菜单 | 两步操作：先点击触发器打开菜单，等待渲染后点击选项 |
| 页面加载等待 | `wails3 dev` 启动后约 20-30 秒 CDP 端口可用，通过检测 `.n-button` 数量确认 Vue 挂载完成 |

> 完整 CDP 脚本用法参见 `scripts/cdp-debug.js`。

### 注意事项

- Playwright 的 `connectOverCDP` 是附加到**已运行的** WebView2，不会打开新浏览器窗口
- 多 worktree 并行时，通过 `CDP_PORT=不同端口 wails3 dev` 避免端口冲突
- 每次调用 `cdp-debug.js` 都是连接 → 执行 → 断开的无状态操作
- **优先使用 `evaluate` 而非 `click`**：Naive UI 的 Modal/Popover 等浮层组件会阻挡 Playwright 的 pointer 事件，JS `element.click()` 可绕过
- **Select 等下拉组件需要两步操作**：先点击打开菜单，再点击选项，中间需要 `sleep 1` 等待渲染
