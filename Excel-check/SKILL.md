# Excel-check — 配置表检查框架

## 结构

```
Excel-check/
├── SKILL.md                 # 本文件：流程、通用规则类型、写新表方法论
└── <Table>/                 # 文件夹 = xlsx 主文件名（可含中文）
    ├── SKILL.md             # 通用规则 + 独有规则（各含结构化 / 语义）
    └── scripts/check_<ScriptId>.py
```

| 名称 | 规则 |
|------|------|
| `<Table>` | = 表文件名（无扩展名），可含中文。例：`Mail`、`ShopGoods_商品表` |
| `<ScriptId>` | **禁止中文**；英文保留，中文改无声调小写拼音。例：`check_Mail.py`、`check_ShopGoods_shangpinbiao.py`。纯英文时与 `<Table>` 相同 |

能脚本化的进脚本；需语境/常识判断的进 LLM。**禁止**在脚本维护易变对照表（如字号→武将名、错别字词表）。

单表 skill 固定四段（空段须注明「无」或「经归纳无」）：

| 层级 | 位置 | 写什么 |
|------|------|--------|
| 通用 | `## 通用规则` → 结构化 / 语义 | 公共 S*/L* **落到本表字段** |
| 独有 | `## 独有规则` → 结构化 / 语义 | 本表玩法专属；**不要**写进本文件 S*/L* 细目 |

---

## 表结构规范（仅两种）

写新表前先判定 **A** 或 **B**；单表 skill 须标明 `表结构：A|B` 与 `主键列`。

### A — 经典行表（绝大多数）

| 行（0-based） | 内容 |
|---------------|------|
| 0 | 中文列名 |
| 1 | 类型（`int` / `string` / `bool` / `E*` / `*[]` 等） |
| 2 | 英文字段名 |
| 3 | `server` / `client` / `server/client` 等 |
| 4 或 5 起 | 业务数据（元数据行数略有增减时，可调 `DATA_START_ROW`） |

**主键**：字段名行中用于唯一标识的列，**名称不限**（`Id` / `*Id` / `Dan` / `key` / `ShopType` 等）。不要因不叫 `Id` 就判不合规。

**空列丢弃（仅 A）**：Excel 第 2 行（类型）与第 3 行（字段名）对该列皆空 → 该列不检（读表丢弃）。

### B — Global 系（竖向键值）

首行即列名：`name` | `value` | `type` | `sign` | `description`；从第 2 行起为数据。  
例：`Global_*`、`BattleGlobal_*`、`GuildCityName_*`。主键一般为 `name`。  
**不要**套用 A 的类型行@1 / 字段名行@2 / 数据@4。

### 公共读表约定（A/B；不可擅自例外）

| 约定 | 适用 | 含义 / Agent 禁止 |
|------|------|-------------------|
| 连续空 3 行截断 | A/B | 主键列连续空 3 行后截断、其后不检。**禁止**因后面还能看到数据就不截断 |
| `#` 分区行跳过 | A/B | 主键以 `#` 开头为分区/注释，跳过不检，且不计入空行截断。**禁止**当业务行校验 |
| 第 2、3 行皆空列丢弃 | 仅 A | 见上。**禁止**因数据区有值就强行纳入未命名列（白名单须用户确认） |
| `DATA_START_ROW` | 仅 A | 仅元数据行数明显不同时可调；**不得**借机改截断语义或把 B 当 A 读 |
| 表结构 A/B | 全部 | 不得写错类型或用错读法 |

摸表发现「空 3 行后仍有行」：仍截断 → 汇报约 N 行未检 → **仅当用户明确要求**才写本表不截断例外。  
不得把「放宽公共读表约定」写成默认可归纳出的独有规则。

路径由用户提供；默认不读外联表（单表另有说明除外）。依赖：`pip install pandas openpyxl`。

## 两阶段校验

| 阶段 | 执行者 | 规则集 |
|------|--------|--------|
| 1. 结构化 | 脚本 | 通用结构化 + 独有结构化 |
| 2. 语义 | Agent（LLM） | 通用语义 + 独有语义。有文本描述字段时**至少执行 L1**；确认皆无才标「仅结构化」 |

字段 ↔ 规则多对多（一字段可挂多条）。例：Mail 的 `Title` = S2 + L1 + 独有语义（Title↔Sender）。

### 结构化规则（S*）— 通用类型

| 编号 | 规则 | 说明 / 来源例 |
|------|------|----------------|
| S1 | 主键类型与唯一 | 主键列类型正确、不重复 |
| S2 | 必填 / 非空 | 如 `Title` |
| S3 | 固定前缀 / 模板开头 | 如 Body 的 `<color=…>占位</color>` |
| S4 | 条件 → 枚举值 | 如 Title → `SenderType` |
| S5 | 条件 → 固定字符串 | 如特定 Title → `Sender`=`系统` |
| S6 | 跨行一致性 | 同键多行某列相同 |
| S7 | 成对字段联动 | 如 `Receiver` → `ReceiverType` |
| S8 | Excel 单元格类型 | 须文本的列不能是数值型 |
| S9 | 正则 / 格式串 | 如 Item `{道具id;数量}` |
| S10 | 长度 / 位数约束 | — |
| S11 | 时间区间成对与先后 | 同空或同有；开始≤结束 |
| S12 | 类型行符合预期 | 有值时，须符合该列**类型行**声明（与 S8 不同：S8 看 Excel 底层单元格类型） |

#### S12 类型行符合预期（必须，表结构 A）

对数据行每个**有值**字段，按类型行（0-based 行 1）声明做形态校验；空值不报（必填见 S2）。表结构 B（Global 系）按 `type` 列对 `value` 校验，语义同下。**类型只认类型行/type 列，禁止用字段名（如 `Is*`）推断是否为 bool。**

| 类型行声明 | 有值时要求 |
|------------|------------|
| `int` / `long` / `int32` / `int64` 等整型别名 | 可解析为整数（允许 `1.0` 这种整值浮点写法） |
| `float` / `double` | 可解析为数字 |
| `bool` | `true`/`false`/`0`/`1`/`yes`/`no`（大小写不敏感）；兼容 Excel 读出的 `0.0`/`1.0` |
| `string` | 有值即通过（内容形态不在本条约束；文案质量见 L1） |
| `int[]`（或元素为整型的 `*[]` 且可判定为 int 列表） | 单个 int，或逗号分隔 int 列表（可去空格；可带 `[]`，如 `[1,2,3]`） |
| `string[]` | 逗号分隔的非空片段 |
| `E*`（如 `ESkillId`、`EAudioId`） | 标识串（`^[A-Za-z][A-Za-z0-9_]*$`）或可解析 int（兼容数值枚举） |
| `E*[]` | 逗号分隔，每项符合上条 `E*` |
| `ItemCfg` / `ItemCfg[]` 及 `{…}[]` 等复合配置 | 非空；细格式由单表 S9/独有规则补充，本条不做词表级解析 |
| 其它未识别类型 | 不报（避免误杀）；单表可加独有或 S9 |

与已有规则关系：S1 仍管主键；S12 管**其余列**（主键列若也走字段循环，与 S1 重复报可接受，脚本宜跳过主键列）。S9 管业务格式串；S12 管类型行基础形态。

### 语义规则（L*）— 通用类型

公共通用语义目前仅 **L1**。人物匹配、身份矛盾、玩法文案对应等 → 写单表 **独有语义**（样例：[Mail](Mail/SKILL.md)、[Hero](Hero/SKILL.md)、[SkillUI_技能表现表](SkillUI_技能表现表/SKILL.md)），不要往本文件堆编号。

| 编号 | 规则 |
|------|------|
| L1 | 文案质量（错字 / 漏字 / 病句 / 标点） |

明确不一致才报；吃不准标「需人工确认」；不因缺外链表跳过。

#### L1 文案质量（必须）

文本描述列必须挂 L1，写入单表 `## 通用规则` → `### 语义规则`（列清单）；由 LLM 审，**禁止**脚本维护错别字词表。

**纳入（命中任一）：** 字段名含 Name/Title/Des/Text/Tip/Content/Body/SkillText/Allusion/Sender/台词提示等；或类型 `string` 且样例为自然语言。  
**不纳入：** 主键/外键、枚举码、时间、格式串、资源路径、拼音、`bool` 等（单表另有说明除外）。

| 项 | 报 issue |
|----|----------|
| 错字 | 别字、同音错用、明显写错的专有名词 |
| 漏字 | 缺字导致不通或歧义 |
| 病句 | 成分残缺、搭配不当、明显语病 |
| 标点 | 错用/漏用/多余，或中英文标点混用破坏阅读 |

有值才审；空不报。先剥 `<color=…>` 等标签再审正文。  
有文本描述列却写「通用语义：无」→ **未完成**写表流程。

## 表独有业务规则 — 怎么归纳

不要凭空列问题清单。读已有单表 `## 独有规则`（活教材），学**写法**再对照新表落条文；具体条文只进单表，不进本文件 S*/L*。

| 可迁移特性 | 形态 | 痕迹（风格） |
|------------|------|--------------|
| 业务钥匙列 | 若 A 匹配 → B 必须… | Mail `Title`；Recharge `Name` |
| 可执行匹配 | 精确串 / 前后缀 / 正则 / 枚举 | Recharge `^(\d+)元` |
| 一条件多列 | 同条件约束多字段 | Mail Title→SenderType/Sender/… |
| 跨行取值 | 本行 = 另一行（钥匙定位）某列 | Recharge 典藏 RelateId |
| 分叉变体 | 同类名因另一列拆多条 | Recharge 升级档 vs 直购档 |
| 跨行一致 | 同钥匙多行某列相同 | Mail 同 Title→同 Sender |
| 硬/软分流 | 定值进脚本；常识进独有语义 | Mail 人物匹配 |

能定死期望 → 独有结构化；需语境 → 独有语义；都推不出 → 注明「经归纳无」。

**落盘位置：** 业务细目 → 单表独有；S*/L* 落地 → 单表通用；仅**可跨表复用的新类型**才在本文件 S*/L* 新开编号。

### 使用者后续补充（必须）

使用者可直接改单表 `SKILL.md`。Agent 按用户要求**补规则前**须对照该表已有通用+独有（及脚本）：

| 情况 | 处理 |
|------|------|
| 实质重复 | 先反馈，勿落盘；问保留/合并/取消 |
| 冲突 | 先列双方，停止实现；问以谁为准 |
| 无重复无冲突 | 再写入，并视需要改脚本 |

单表 skill **必须**含 `## 补充规则时（必须）`（见下方骨架，表意不得弱于上表）。只改 skill 不改脚本也合法，检查以 skill 为准并对齐实现。

## 脚本 CLI 与检查汇报

```bash
python "<Table>/scripts/check_<ScriptId>.py" "<xlsx 路径>"
python "<Table>/scripts/check_<ScriptId>.py" "<路径>" --json
python "<Table>/scripts/check_<ScriptId>.py" "<路径>" --semantic-json
```

| 参数 / 退出码 | 含义 |
|---------------|------|
| 默认 | 结构化问题 + 待语义行数 |
| `--json` | 完整 JSON（含 `semantic_rows`） |
| `--semantic-json` | 仅待 LLM 行 |
| `0` / `1` / `2` | 结构化无问题 / 有问题 / 文件不存在等 |

Issue：`<主键列>=<值> | <展示列>=<值> | <字段名> | <问题说明>`（展示列无则 `-`）。

**Agent 检查一张表：** 读单表 skill → 跑脚本（需要时 `--semantic-json`）→ 语义按单表标准分批（建议 ≤50 行/批）→ 汇报路径 + **逐条 Issue 原文** + 语义问题 + 总数。  
**禁止**用分类汇总表/只报数量代替 Issue 行（用户明确要求「只摘要」除外）。可先保留脚本摘要行再列 Issue。

## 如何写一张新表的检查 skill

须 **1 → 1.5 → 2 → 3** 做完再落盘。

### 1. 通用规则（S*/L*）

1. 判定 A/B；确认字段、样例、主键；按公共读表约定落地  
2. 拉齐本文件 S*/L* 与已有单表样例（Mail / Recharge / SkillUI 等）  
3. 双向打标；**L1** 挂上所有文本描述列；玩法语义进独有  
4. 结构化进脚本；语义进 skill + 检查时 LLM（`--semantic-json`）  
5. 空 3 行后仍有数据：截断 + 汇报提示，不得先改不截断  
6. 有文本列未写 L1 → 不得落盘为「通用语义：无」

### 1.5. 独有规则（必做）

按上文「怎么归纳」写入本表独有结构化 / 语义并实现；推不出则注明「经归纳无」。

### 2. 回补公共（仅新类型）

仅当出现可复用且本文件没有的规则**类型**时，才新开 Sx/Lx。表内业务条目不回补。

### 3. 向用户汇报（必须）

```
## 本表规则清单：<Table>
### 通用规则
- 结构化：…
- 语义：…（须含 L1 字段清单，或写明无文本列故 L1 不适用）
### 独有规则
- 结构化：… / 经归纳无
- 语义：… / 经归纳无
### 公共类型回补
- 无 / 新开了 Sx/Lx
### 读表约定
- 表结构：A / B；主键列：…
- `#` 分区行：已跳过 / 用户确认例外…
- 空 3 行截断：已遵守 / 用户确认例外…；截断后未检：无 / 约 N 行
### 产物
- …
```
