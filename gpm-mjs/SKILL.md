通用命令（登录、删除二次确认、`--json` 用法等）见全局 skill `gpm-cli`；本文件只写**名将杀专有规则**。

## 工具检查与自动安装（每次任务开始前）

执行任何 GPM 操作前，**必须先探测 CLI 是否可用**；不可用则自动安装，不要要用户手动找安装包。

### 1. 探测命令入口

按顺序尝试，**第一个成功的即为本次会话的 `GPM` 命令前缀**（后文 `python3 -m gpm` 均替换为探测结果）：

```bash
gpm-cli --help
python3 -m gpm --help    # Linux / macOS
python -m gpm --help     # Windows 常见
```

探测示例（PowerShell）：

```powershell
if (Get-Command gpm-cli -ErrorAction SilentlyContinue) { "gpm-cli" }
elseif (python -m gpm --help 2>$null) { "python -m gpm" }
```

### 2. 未安装时自动安装

**三个命令都失败** → 运行与本 `SKILL.md` **同级目录**的离线安装脚本：

```powershell
# Windows（脚本与 SKILL.md 同在 gpm-mjs 目录）
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill目录>\gpm-cli-install.ps1"
```

- `<skill目录>`：本 skill 所在路径，通常为 `%USERPROFILE%\.cursor\skills\gpm-mjs`
- 默认安装 **CLI + gpm-cli skill**；若仅需 CLI、且已有 `gpm-cli` skill，可加 `-CliOnly`
- 脚本**仅支持 Windows PowerShell**；Linux/macOS 无法运行时，提示用户在本机 Windows 执行上述命令，或联系提供方获取 wheel 包

安装完成后**重新探测**；仍失败则展示脚本输出并停止，不要继续建单。

### 3. 登录与项目

CLI 可用后，确认已登录并选中名将杀：

```bash
<GPM> login          # 未登录时执行；SSO 推荐
<GPM> init           # 未选中 cards 时执行，选「名将杀」
```

- `<GPM>` = 步骤 1 探测到的前缀（如 `gpm-cli` 或 `python -m gpm`）
- 登录/项目未就绪时引导用户完成，再继续业务操作

## 核心原则

1. **按字段规则填单** — 各字段收集、推断、默认值见 [templates/bug-create.md](templates/bug-create.md)「Agent 填单规则」。可猜测的字段须标注（猜测）；经办人、版本树等必须指定或确认的规则不得跳过。
2. **先查后填** — 枚举值、成员 ID 通过 `python3 -m gpm metadata` / `python3 -m gpm version-tree list` 获取，不用硬编码 ID（选项可能变更）。
3. **展示确认** — 创建前用表格展示摘要（含猜测/默认标注），其余确认后再执行 `issue create`。
4. **人类可读** — 对用户展示编号、标题、类型名、状态名、人名；不暴露内部 ID（JSON 构造除外）。
5. **标题规范** — 缺陷标题格式：`【细分】一句话概括`。`【】` 为模块的进一步细分（如模块「武将」→ `【关羽】…`），详见 bug-create 模板。
6. **版本与版本树必填且一致** — `versionId` 和 `versionTreeId` 必须同时填入，默认值按星期规则自动推断（见下方「版本 & 版本树默认规则」），无需向用户确认。
7. **格式不明必引导** — 用户问「怎么建单」、消息无法解析、或必填信息缺失导致**不能安全建单**时，**禁止硬猜或空建**；须说明缺什么，并给出对应格式示例（见「建单格式引导」）。

### 数据读取方式

**已知限制**：Bitable Open API 的 filter 参数对所有字段不生效（服务端 bug），分页仅返回 500 条。**采用 Excel 导出方案**替代 API。

用户上传导出的 Excel 文件后：
1. 读取「项目需求池」sheet，按 `需求单号`（需 `str()`）键索引
2. 读取「任务总表」sheet，用正则 `r"(\d{8,14})"` 提取 `需求单号` 键索引
3. 用户提供需求单号 → 精确定位需求行 + 子任务列表
4. 子任务筛选：
   - **常规子任务**：类型为 `前端`/`后端`/`策划`/`客户端`，名称不含「联调」
   - **验收类子任务**：类型为 `UI`/`特效`/`spine`/`音效`，见下文「验收类子单建单规则」

```bash
# Excel 读取（Python openpyxl）
wb = openpyxl.load_workbook('<用户上传的xlsx文件>')
ws1 = wb['项目需求池']  # 需求表
ws2 = wb['任务总表']    # 任务表
```

### 字段映射规则

#### 1. 需求开发单

| `version` | 所属版本字段 | **需人工映射**，见下文 |

#### 任务类型 → GPM issueTypeId 映射

| Bitable 任务类型 | GPM 类型 | issueTypeId |
|-----------------|----------|-------------|
| 前端 | 前端子任务 | 1030 |
| 后端 | 后端子任务 | 1036 |
| 策划 | 策划子任务 | 1037 |

#### 验收类子单建单规则（UI / 特效 / spine / 音效）

适用于 Bitable 任务类型为 `UI`、`特效`、`spine`、`音效` 的行。与常规前端/后端/策划子任务**分开处理**。

**前置条件**：该需求在「任务总表」中**必须存在**任务类型为 `前端` 的子任务行；否则 **UI/特效/spine/音效 一律不创建**（前端子任务本身仍按常规子任务流程创建）。

| GPM 字段 | 规则 |
|----------|------|
| `summary` | `{需求单号} {任务名称}-{单子类型}验收` |
| `issueTypeId` | **1030（前端子任务）**（不用 UI子任务/动效等独立类型） |
| `assigneeId` | **与锚定前端子任务经办人相同**（不用 Excel 中 UI/特效 等行的负责人）。多条前端时：优先匹配需求池「前端」字段对应负责人；否则取任务表中**第一条**前端子任务的负责人 |
| `reporterId` | 与父需求开发单相同 |
| `customFields[788]` | 与 `assigneeId` 相同（开发人员=经办人） |
| `parentIssueId` | 父需求开发单的 `issueId` |
| `versionId` / `versionTreeId` | 与父需求开发单相同 |

**标题示例**：

| Excel 任务名称 | 任务类型 | GPM 标题 |
|---------------|----------|----------|
| 重伤相关时机点优化 | 特效 | `202606223550 重伤相关时机点优化-特效验收` |
| 登录界面迭代 | UI | `202606223550 登录界面迭代-UI验收` |

**去重**：标题须同时包含需求单号、原任务名称、`-{类型}验收` 后缀，且 `issueTypeId=1030`（前端子任务）。

**汇总报告**：验收类单子单独列出，类型名展示为 `前端子任务 · {类型}验收`（如 `前端子任务 · 特效验收`）。

### 用户 ID 映射

Bitable 人员字段格式：
```json
[{"email": "lidongsheng1@ztgame.com", "en_name": "大闸蟹(李冬生)", "id": "ou_7b40308405b24776fcd2d9459698895f", "name": "大闸蟹(李冬生)"}]
```

映射方式：
1. 用 `name` 字段（如 `大闸蟹(李冬生)` 或 `刘俊杰`）匹配 `python3 -m gpm metadata members` 中的姓名
2. 部分 Bitable 名称带括号前缀（如 `大闸蟹(李冬生)`），在 `python3 -m gpm metadata members` 中可能是 `李冬生` 或 `MrLiu(刘俊杰）`
3. 优先匹配姓名（括号后的部分），再降级模糊匹配
4. 匹配失败时向用户确认

## 去重规则（所有场景通用）

创建前**必须先搜索** GPM 已有工作项，避免重复建单：

```bash
python3 -m gpm issue list --sprint <当前活跃迭代> --assignee <人员> --size 100
```

**匹配规则**：

| 单子类型 | 判定"已存在"的条件 |
|----------|------------------|
| 需求开发单 | 标题中包含目标需求单号（如 `20241202002`），且 `issueTypeId=1035` |
| 子任务单 | 同时满足：① 任务类型一致（验收类用前端子任务 issueTypeId=1030）② 标题中包含目标需求单号 ③ 标题（或描述）与任务名称匹配（验收类须含 `-{类型}验收` 后缀） |

**命中后**：
- 需求开发单已存在 → 复用，不重建；展示已有单子信息
- 子任务单已存在 → 复用，检查 `parentIssueId` 是否已关联到父需求，未关联则补关联
- 不存在 → 正常走新建流程

## 建单场景

### 确认策略（场景1/2/3 通用）

**默认直接创建，仅在缺失必填信息时询问。**

| 情况 | 行为 |
|------|------|
| 所有必填字段都有值（含默认值） | 直接创建，不展示确认 |
| 必填字段缺失且无默认值 | 询问用户确认 |
| 非必填字段缺失 | 直接创建，结果中标注 ⚠️ 缺失 |

**GPM 必填字段速查**：
- 需求开发单(1035)：summary, issueTypeId, versionId（priorityId 默认 459）
- 前端子任务(1030)：summary, issueTypeId, versionId
- 后端子任务(1036)：summary, issueTypeId, versionId
- 策划子任务(1037)：summary, issueTypeId（versionId 可选）

创建后一次性汇总报告，格式：
```
202605293434 端午活动：白泽问答 | 汇总

【需求开发单】#17418（已有）⚠️ QA缺失
【子任务】
  #17459  前端子任务 · 杨万杰 🆕
  #17460  策划子任务 · 万昱君 🆕
  #17461  前端子任务 · 特效验收 · 杨万杰 🆕
跳过：联调/测试 ×2；无前端子单跳过 UI/特效/spine/音效 ×3
```

### 场景1：需求单号全量建单（从多维表格同步）

用户提供需求单号（如 `20241202002`）：

1. **Excel 查需求**：按单号索引需求行（需 `str()` 转换）
2. **Excel 查任务**：按单号索引子任务；常规子任务筛选 前端/后端/策划；验收类子任务筛选 UI/特效/spine/音效，并按「验收类子单建单规则」判断是否有前端子单
3. **逐条去重（⚠️ 不可缓存）**：
   - 每个需求建单前必须实时查询 GPM，不能用提前拉取的列表缓存
   - 需求开发单：`python3 -m gpm issue list --size 500` 搜单号，逐个 grep
   - 子任务：`python3 -m gpm issue get <父issueId>` 看 `children`
   - **原因**：批量建单过程中 GPM 在变化，缓存的列表会过时导致重复建单
4. **按确认策略决定**：必填都有值 → 直接创建；缺失 → 询问
5. **创建**：按需创建缺失的需求开发单、常规子任务、验收类子任务（无前端子单则跳过验收类）

### 场景2：指定任务建单（需求单号 + 任务名称 + 类型）

用户提供需求单号 + 任务名称 + 任务类型：

1. **Excel 查需求**：确认需求存在，获取版本等信息
2. **Excel 查任务**：匹配指定任务名称
3. **GPM 去重**：确认需求开发单是否存在，搜索子任务
4. **按确认策略决定** → 直接创建或询问 → 汇总报告

### 场景3：独立子任务建单（无需求关联）

用户直接给任务描述 + 任务类型，不需要关联需求开发单：

1. **去重搜索**：GPM 中搜同类型 + 相似标题，不要求完全匹配
2. **命中相似单 → 展示给用户确认**，用户决定复用还是新建
3. **按确认策略决定** → 直接创建或询问 → 汇总报告
4. 版本和版本树按星期规则自动推断（见上方「版本 & 版本树默认规则」），经办人必须指定

## 对话规范

用户消息以关键词开头，直接触发对应场景，无需额外指令。

### 缺陷建单

```
bug：<问题描述>
缺陷：<问题描述>
```

描述一句话即可；其余字段由 Agent 推演并标注（猜测），**经办人未给则单独询问**。冒号可用中文 `：` 或英文 `:`。

> 例：`bug：秦舞阳发动燕有勇士给队友摸牌，下一次出杀没有中毒效果`

### 建需求单+子任务（场景1）

```
需求：<需求单号>
```

需求单号为 **8～14 位数字**。从多维表格同步该需求及子任务；需用户上传 Excel 时先说明。

> 例：`需求：20241202002`

### 建指定子任务（场景2）

```
任务：<需求单号> <任务名称> <任务类型>
```

三部分用**空格**分隔；任务类型限 `前端` / `后端` / `策划`。

> 例：`任务：20241202002 充值sdk接入 前端`

### 建独立任务（场景3）

```
任务：<类型>，<描述>，<经办人>
```

用**中文逗号** `，` 分隔三段；类型限 `前端` / `后端` / `策划`；经办人必填。

> 例：`任务：前端，loading性能优化，刘江波负责`

### 查改类（无固定格式）

改状态、查待办、看详情等，直接说即可，例如：`#17444 改成已修复`、`看看我的待办`。

## 建单格式引导（必遵）

**以下任一情况，不得尝试建单，必须先回复格式说明：**

| 触发条件 | 处理方式 |
|----------|----------|
| 用户问「怎么建单」「如何提单」「建单格式」「能建什么单」等 | 回复**完整格式指南**（下方模板 A） |
| 有建单意图但**无** `bug`/`缺陷`/`需求`/`任务` 关键词，且不是查改 | 回复模板 A，并据用户原话提示最接近的格式 |
| 有关键词但**无法解析**（缺冒号、段数不对、类型非法等） | 回复**针对性提示**（下方模板 B～E）+ 正确示例 |
| 格式正确但**必填项缺失**且无法安全默认 | 说明缺什么、给该场景的格式示例，**不要建单** |

**解析优先级**（从上到下匹配，命中即停）：

1. `^(bug|缺陷)[：:]\s*(.+)$` → 场景：缺陷；必填：问题描述（第 2 组非空）
2. `^需求[：:]\s*(\d{8,14})\s*$` → 场景1；必填：需求单号
3. `^任务[：:]\s*(\d{8,14})\s+(.+?)\s+(前端|后端|策划)\s*$` → 场景2；必填：单号 + 任务名 + 类型
4. `^任务[：:]\s*(前端|后端|策划)[，,]\s*(.+?)[，,]\s*(.+)\s*$` → 场景3；必填：类型 + 描述 + 经办人
5. 其余 → 无法解析

**缺陷单额外说明**：`bug：` 后只有一句话也可建单；但若**连问题描述都没有**（如仅 `bug：`、`建个bug`），视为信息不全，用模板 B。

### 模板 A — 完整格式指南

用户问怎么建单，或完全无法判断场景时使用：

```
名将杀 GPM 建单请用以下格式之一（复制后改内容即可）：

① 缺陷 / Bug（一句话描述现象即可，其余我来补）
   bug：<问题描述>
   例：bug：秦舞阳发动燕有勇士后，下一次出杀没有中毒效果

② 按需求单号同步（需已上传版本研发排期 Excel）
   需求：<需求单号>
   例：需求：20241202002

③ 在指定需求下建子任务（空格分隔三段）
   任务：<需求单号> <任务名称> <前端|后端|策划>
   例：任务：20241202002 充值sdk接入 前端

④ 独立子任务（中文逗号分隔三段，经办人必填）
   任务：<前端|后端|策划>，<任务描述>，<经办人>
   例：任务：前端，loading性能优化，刘江波负责

查待办、改状态不用上述格式，直接说：
   看看我的待办
   #17444 改成已修复
```

### 模板 B — 缺陷格式不对 / 信息不足

```
缺陷建单请用：

  bug：<问题描述>
  或  缺陷：<问题描述>

请补充「出了什么问题」；一句话即可。
例：bug：关羽【武圣】对目标造成伤害后，体力未减少
```

### 模板 C — 需求单号格式不对

```
需求同步建单请用：

  需求：<8～14位需求单号>

你发的内容无法识别单号。请改成例如：
  需求：20241202002

说明：场景1需配合多维表格 Excel，若尚未上传请先提供导出文件。
```

### 模板 D — 场景2 子任务格式不对

```
在指定需求下建子任务，请用空格分隔三段：

  任务：<需求单号> <任务名称> <前端|后端|策划>

你缺了：{列出缺失项，如「任务名称」「任务类型」}

正确示例：
  任务：20241202002 充值sdk接入 前端
```

### 模板 E — 场景3 独立任务格式不对

```
独立子任务请用中文逗号分隔三段：

  任务：<前端|后端|策划>，<任务描述>，<经办人>

你缺了：{列出缺失项，如「经办人」}

正确示例：
  任务：前端，loading性能优化，刘江波负责
```

### 回复要求

- **先一句话说明原因**（无法解析 / 缺 xxx / 用户在问格式）
- **再给对应模板**，不要只回「格式不对」
- 用户**明确在问格式**时给模板 A；能判断场景的只给 B～E，避免信息过载
- 格式正确仅缺经办人等人名时：点名缺什么，**不要**回完整模板 A

## 重要约束

1. **去重优先**：任何创建前必须先搜 GPM，匹配到则复用
2. **🚫 禁止缓存去重结果**：批量建单不能先拉一次 GPM 列表当缓存用，必须每条实时查询，否则 GPM 数据变化会导致重复建单
2. **子任务去重用 children**：`python3 -m gpm issue get <父编号>` 的 `children` 字段列出所有子任务，比命令行 grep 更可靠
3. **parentIssueId 用 issueId**：子任务关联父单时，`parentIssueId` 填父单的 `issueId`（如 141842），不是 `issueNum`（17418）
4. **versionId / versionTreeId**：创建 JSON 中版本字段是 `versionId`（字符串）和 `versionTreeId`（字符串），不是 `version` 和 `versionTree`
5. **QA/经办人默认为测试负责人**：Excel 子任务中找「测试」类型的负责人；无测试任务或负责人为空 → 默认李冬生(4510)
6. **未映射类型跳过**：任务类型非前端/后端/策划/客户端，或名称含「联调」→ 跳过不创建；UI/特效/spine/音效 按「验收类子单建单规则」处理（无前端子单时不创建）
7. **分批创建**：子任务多于 5 个时，先确认需求开发单存在，再逐批创建子任务
8. **失败不中断**：子任务创建失败不影响其他子任务，汇总汇报成功/失败数
9. **关联修复**：复用已有单子时，检查 `parentIssueId` 是否正确关联，未关联则补关联
